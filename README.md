# lead

本地运行的 AI 社媒运营平台实现，当前验收状态如下。通过对话介绍业务，Agent 保存独立的业务资料与运营偏好，后台独立调度工作，并通过持久化 Camoufox 浏览器执行任务。

本机地址：**http://127.0.0.1:3100**。本轮本地交付与使用范围见 [LOCAL_READINESS](docs/LOCAL_READINESS.md)。

## 启动与关闭

本次环境已安装依赖。Docker Desktop 保持运行，在项目目录执行：

```sh
.venv/bin/python scripts/run.py start
.venv/bin/python scripts/run.py status
.venv/bin/python scripts/run.py stop
```

本地管理器启动前端、API、任务 Worker、浏览器网关及独立备份监控，并在子进程意外退出后重新启动。数据库与 Temporal 使用持久化 Docker 卷；关闭应用不会删除数据。电脑休眠/关机期间不执行任务，恢复并启动后由 Temporal 继续处理。

进程状态和诊断在 `.state/`，默认只监听本机环回地址。默认采用本地所有者模式；已实现 OIDC、工作室隔离和成员权限，尚未配置外部身份服务。维护者配置见 [运维、权限与恢复](docs/OPERATIONS.md)。不要将开发配置直接改为监听公网地址。

## 管理后台

在工作台左下角进入「管理后台」，或访问 **http://127.0.0.1:3100/admin**。包含配置就绪、资料初始化、Agent 额度与集中管理、模型用量、渠道策略与规则、经验审核、数据与归因、创建引导、模型与工具、可选模型、品牌与知识、调度与异常、通知配置和变更记录。

- 所有者保留完整权限；运营成员可按功能授予后台写入权限，查看成员始终只读。「成员权限」可限制可访问的 Agent，限制同时作用于接口、数据读取和实时刷新。成员身份/角色和外部通知凭据仅由所有者维护；工作室必须保留一位有效所有者。旧版额度接口也执行对应权限与版本校验。
- 每日 token 额度支持工作室默认、Agent 独立设置及整批调整。消耗与未核对预留不因调整而清空；默认仍为每天 UTC 00:00（北京时间 08:00）重置。
- 渠道策略按通用模板、Agent、账号目标逐级覆盖，支持恢复继承。草稿不参与运行，发布后的策略用于后续规划；已有计划保留完整策略快照。策略不扩大真实渠道能力及账号授权。
- 创建引导可维护固定三步下的字段说明、必填规则、默认值、默认渠道和策略选项；预览不会创建 Agent。已开始的创建流程保留原模板版本，关闭后可继续填写。
- 每次草稿、发布和回滚原子保存版本、修改人、说明与前后内容。过期版本写入返回冲突，历史表不允许运行角色修改或删除。权限和数据范围限于当前工作室。
- 模型与工具按工作室默认、Agent 覆盖生效。可分别选择对话、规划、研究模型，维护超时、输出与调用上限，以及网页研究、社群线索研究、素材制作开关。可选模型来自服务端默认模型及 `LEAD_ALLOWED_MODELS`，凭据和接口地址仍只在服务端维护；检查连接只读取模型列表，不发送生成请求。
- 品牌与知识支持品牌语气、语言、定位、事实、禁用表达、素材要求，以及带来源、确认状态和有效期的文本资料。仅已确认、未过期的资料进入模型上下文，一次最多 6 条、每条 6000 字。禁用表达在文字发布及原创素材文案检查中执行。品牌配置发布会增加现有 Agent 配置版本并撤回旧方向的排队内容。
- 调度与异常支持时区、跨夜工作时段、星期、工作室并发上限、发布重试和连续失败暂停。默认不限制工作时段，同时最多 3 个 Agent 自动工作，发布最多尝试 3 次，同类连续失败 5 次自动暂停。对话不受工作时段限制，外部结果不确定时继续核对原提交，不重发；手动恢复会重新累计失败。
- 通知配置接入站内提醒。真实额度、登录失效、连续失败、待核对动作及知识过期由 Worker 定期收集，持续异常只提醒一次；可选接收角色或工作室成员、额度预警比例、免打扰和恢复后再次出现的冷却期。每位成员有独立的已读记录，工作台「通知」入口可直接进入。站内接收范围在生成时保留，Webhook 与邮件在「外部通知」中单独配置启用。

第三期补齐资料初始化与就绪检查：

- 「资料初始化」提供带来源和内容预览的研究包：11 个渠道共 33 套通用方案、创建引导的六项说明与示例、通用资料规范。对产品网址为 `seka.one` 的 Agent，另外填充专属品牌资料和 11 个渠道的业务方案，既有 180 个选题、30 篇首稿/分镜进入可编辑配置。官网事实核对于 2026-10-30，产品页面资料有效至 2026-11-29，过期后需重新核对。品牌名称和业务事实放在对应 Agent 下，通用模板不写入 Seka 身份。
- 初始化只发布未编辑的项，已有草稿和版本全部保留；重复执行不会覆盖。资料包摘要变化时要求刷新预览。每项经由同一权限、版本、审计和发布流程，品牌更新继续撤回旧方向的排队内容。Seka 业务策略的后续人工修改优先于静态首稿示例，承接路径只能填写当前产品网站内的路径。
- 「配置就绪」只读核对业务、模型凭据、可用知识、渠道账号/目标/授权/平台条件/已验证格式，以及按归因配置核对的网站和服务端回传新鲜度。凭据存在不等于模型连接已通过；资料齐全不代表已有发布或获客结果。缺少回传显示未知，不显示虚构的零结果。

后台剩余功能按以下顺序推进，第三期先交付 P0：

|---|---|---|

| P1 | 渠道与账号规则管理 | 已落地渠道、Agent、目标三级版本化规则，收紧格式、发布频率和社群操作，提交前再次核对 |
| P1 | 数据与归因配置 | 已落地目标定义、归因窗口、有效访问时长、新鲜度与回传异常提醒；每次访问保存规则版本 |
| P1 | Agent 集中管理与策略经验 | 已落地搜索筛选、控制版本校验的批量暂停/归档、经验草稿与审核、明确提炼通用模板草稿 |
| P2 | 细分成员权限、成本定价、外部通知 | 已落地功能权限与 Agent 数据范围、调用开始时的计价快照、Webhook/SMTP 加密配置与持久发送记录 |

新环境先运行 `.venv/bin/python scripts/migrate.py`，再由所有者在「资料初始化」预览并发布。后台配置和版本历史随数据库备份保存；本机浏览器的未提交草稿仅用于恢复编辑。

第四期管理能力：

- 「成员权限」在 OIDC 工作室登录模式下添加或撤销成员、调整基础角色、细分功能和 Agent 范围。运营角色默认保留工作台操作，后台写入需明确授权；指定 Agent 范围的成员不能修改影响全工作室的默认配置。本机所有者模式显示说明，不创建虚假的可登录成员。成员策略沿用草稿、发布、回滚和不可修改的历史。
- 「模型定价」维护币种、每百万 token 的普通输入、缓存命中、30 分钟/12 小时缓存写入与输出单价、来源、核对日期、生效时间及长上下文倍率。OpenAI 六个模型的 Standard 参考价核对于 2026-10-30，来源链接随单价保留；可填补未登记模型与缺失的缓存写入单价，保留已有人工单价。当前工作室按正常发布流程初始化参考价。DeepSeek 公开价格存在峰谷和节假日差异，不自动套用单一固定价，需按实际计价约定登记。
- 每次预留 token 时保存当时已生效的计价快照；改单价、预定未来版本和回滚不重算已发生的消耗。缓存命中和写入包含在输入 token 内，分别使用对应单价，避免重复计费；写入时长采用实际回传明细，未回传时仅在明确使用默认缓存时长的请求中推定。多币种分别合计。缺少单价、缓存写入用量/时长或逐次长上下文明细、非标准服务档位时显示未计价，费用摘要明确是已覆盖部分的估算。价格依据：[OpenAI 模型文档](https://developers.openai.com/api/docs/models/gpt-6-luna)、[缓存计价说明](https://developers.openai.com/api/docs/guides/prompt-caching)、[DeepSeek 计价说明](https://api-docs.deepseek.com/quick_start/pricing/)。
- 「外部通知」支持公开 HTTPS Webhook（可选 HMAC 签名）和 TLS/STARTTLS SMTP 邮件。接收地址、签名密钥和邮箱密码由所有者单独加密保存，不返回原文、不写入配置历史或浏览器恢复草稿；配置按渠道选择类别、级别和 Agent 范围。默认关闭，填写真实凭据并发布启用后才发送，保存凭据不发送测试消息，也不补发历史提醒。
- 发送队列沿用异常去重与免打扰时间，HTTP 临时错误有上限和退避；请求结果未知、发送中断及部分邮箱失败会保留状态供所有者核对。已关闭渠道或已恢复异常在发送前取消。未知结果重试需要明确确认重复提醒的可能，记录操作者；Webhook 使用固定通知编号与签名，接收端应按编号去重。Webhooks 签名是 `HMAC-SHA256(secret, timestamp + '.' + 原始请求体)`，对应 `X-Lead-Timestamp`、`X-Lead-Signature: sha256=...` 和 `X-Lead-Event-ID`。

## OpenAI 配置

在部署端 `.env` 配置一份 `OPENAI_API_KEY`，所有 OpenAI 模型共用。后台「可选模型」可读取此账户的模型列表，选择并发布候选，也可手动补充原始模型 ID；支持草稿、版本、回滚，移除运行配置仍在使用的模型会被阻止。「模型与工具」可分别选择对话、规划、研究模型，工作室默认与 Agent 覆盖均生效。「模型用量」按实际调用的服务与模型显示输入、输出、缓存、今日/近 30 天消耗和待核对预留，缺少模型标识的历史保持未记录。

`OPENAI_MODEL` 保留部署默认候选，`OPENAI_ALLOWED_MODELS` 可添加部署候选。`OPENAI_BASE_URL` 默认是官方 `https://api.openai.com/v1`。密钥不会进入后台、聊天或配置历史。后台可分别检查 DeepSeek、OpenAI 连接；检查读取模型列表并核对当前所选模型，生成能力以实际调用为准。模型不存在会明确显示模型名称，修正并发布模型配置后可恢复这类失败对话。

普通对话、运营规划和短研究调用通过 [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text)，使用结构化输出和已有受控工具，并设置 `store=false`。独立 browser-use 研究使用它的 OpenAI Chat 适配。两条路径均保留调用限制及 token 预留和结算。后台用 `openai:<模型名>` 标识 OpenAI，旧的无前缀配置继续使用 DeepSeek。可按任务混用两家服务；缺少所选服务的凭据会明确阻塞，不会自动切到另一家产生消耗。未登记计价的 OpenAI 用量不估造费用。

已有 DeepSeek 环境继续使用原默认值；只有 OpenAI 凭据的环境自动采用 OpenAI。`LEAD_MODEL_PROVIDER=deepseek|openai` 可显式指定未配置 Agent 的默认服务。选择 OpenAI 前在后台确认服务端凭据和连接状态。

## DeepSeek 配置

项目 `.env`：

```env
DEEPSEEK_API_KEY=填写自己的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

密钥每次调用时读取。之前因缺少密钥而阻塞的消息会在配置后自动重新排队；其他失败的消息可在对话中重试。密钥不通过前端发送，不写入消息或数据库；`.env` 被版本控制忽略，权限为 0600。环境文件本身不是加密保险库。

默认每个 Agent 每个 UTC 日最多使用 1,000,000,000（1B）个模型 token。调用前预留，返回后按 provider usage 结算；无法判断是否计费的请求保留预留额。额度按 token 计算，不代表费用报价。「用量与数据」可调整每个 Agent 的每日额度，立即影响当天和后续周期，保留已用量和未核对预留；0 停止新增模型调用。`LEAD_DAILY_TOKEN_LIMIT` 设置全局默认值，Agent 可以恢复使用默认额度。

## 浏览器与网络

混合探索：运行 `.venv/bin/python scripts/install_browser_use.py` 安装独立的 browser-use 运行环境，设置 `LEAD_BROWSER_USE_ENABLED=1`。探索使用无社媒登录的 Chromium/CDP，只开放平台只读研究工具；账号操作和发布继续由 Camoufox 与动作账本执行。browser-use 的模型消耗计入同一 Agent 的每日额度。

每个 Agent 的配置、Cookie、IndexedDB、LocalStorage 分别放在 `.state/profiles/<agent_id>/`。一个配置对应一个独立 Camoufox 进程，跨进程文件锁避免重复启动，同一环境串行执行，不同环境并发执行。默认上限由 `LEAD_BROWSER_CONCURRENCY=3` 控制。

本次固定验证版本：Camoufox SDK 0.5.8 / 浏览器 156.0.1-beta.36。已验证 UA、屏幕、平台、Canvas 像素与存储的重启保持，以及不同配置的独立性。Firefox PNG 导出的每次会话附加信息仍会变化，这不等同于 Canvas 像素或已保存身份配置丢失。没有承诺所有指纹项目不变，或第三方一定判为不同真实设备。

可在 `.env` 为 Agent 绑定固定代理：

```env
LEAD_PROXY_<去掉横线并大写的AGENT_ID>=http://user:password@proxy.example:1234
```

浏览器始终连接本 Agent 的受控本地转发器，由它使用绑定的上游代理。目标 DNS 通过同一代理中的固定公网 DoH 解析并固定到公网 IP；禁止私网和本机控制服务，只有本 Agent 的测试站路径例外。绑定代理失败不回落直连，已用真实浏览器故障测试验证。WebRTC、IPv6、HTTP/3 与预取关闭。

高级设置「检查环境」通过实际浏览器访问 ipify 和 Cloudflare，记录设备采样和两个出口结果。还需设置 `LEAD_EXPECTED_IP_<AGENT_ID>=固定公网IP`，两次观测一致且匹配固定值、配置了上游代理、WebRTC 禁用，才能通过固定出口检查；数据库拒绝把同一已验证出口绑定到多个 Agent。结果有效 15 分钟。此检查不代表第三方一定无法关联身份，也不代替 OS 防火墙及 DNS/WebSocket/地区一致性等完整检测。

默认本地所有者模式允许对自有 Telegram 频道完成显式验证；不会显示为独立出口已经通过。`LEAD_DEPLOYMENT_MODE=production` 时，十一个平台每次新提交前会重新测量出口并核对身份，失败停止提交。新增正式 TLS 连接与服务模板；完整生产安全与部署验收仍未完成。

浏览器远程接管的输入仅在有效接管期内开放，登录资料不进入 Agent 对话。验证码与平台身份验证由用户在浏览器中完成。

## 访问统计

网站像素现在使用独立的嵌入、安装检测、事件设置与测试弹窗；检测通过后自动进入事件测试。获客效果汇总展示访客、会话和事件，事件明细区分次数、人数及接入状态。标准／自定义事件、真实测试码、来源快照与异步支付回传说明见 [网站像素与事件接入](docs/PIXEL_EVENTS.md)。

在 Agent 的「获客效果 → 接入网站统计」生成网站代码及推广链接。公网使用需要先配置 `LEAD_PUBLIC_URL=https://实际部署地址`；当前本机链接只能在本机使用。

「获客效果 → 推广链接 → 配置」可单独设置推广落地页，默认沿用产品网址。保存后常规发布与社群推广都优先使用此链接，自动追加一个短参数，例如 `?lr=tg_…`，最多增加 18 个字符；保留原有业务参数、重复参数与锚点。旧 `lead_ref` 链接及网站代码的安装方式继续兼容。配置修改会撤回旧配置下尚未执行的排队内容，已发布链接继续有效。

获客效果中的社媒明细只展示当前已连接的平台，同平台账号合并统计，最多约四行后在表格内滚动。点击、访问、有效访问和目标转化采用近 30 天口径，发布数为累计正式发布；测试站和连接验证消息不计入发布成果。网站或服务端回传未接入、已过期时，对应数据保留未知值。

- 推广链接请求仅算点击，已识别的预览机器人不计入有效点击。
- 网站实际回传会话后才计访问；仅把带当前 Agent 推广归因的会话计为其获客。
- 当前有效访问规则 `engaged-v1`：页面前台活跃至少 10 秒，服务器同时检查两次事件的间隔。
- 数据标记为 `client_observed`，不是经过服务端验证的成交。服务端转化使用独立回传凭据并与归因会话关联，未接入或数据过期时显示空值。接入方法见 [CONVERSIONS.md](docs/CONVERSIONS.md)。

客户端埋点可被伪造，当前规则不能等同于反欺诈认证或保证人工访问。

## Telegram 实号验收

1. 在 Agent 对话中提供业务信息。连接账号 → Telegram，在专属浏览器内登录并点击「登录完成」。
2. 点击「免费启动」或「恢复」，一次委托 Agent 运营该已登录账号。恢复只要求真实登录，不要求用户先创建频道。
3. Supervisor 自动筹备 Telegram：核对已有绑定的自有频道；尚未绑定时创建业务专用广播频道、跳过联系人邀请并设置公开链接。频道名称来自业务名，操作仅通过 Telegram Web K 页面。
4. 系统依据账号委托自动保存具体频道授权并安排一次连接验证，无需用户再次点卡片。范围仍为该频道发布、每天最多 3 条；不私信、不邀请联系人、不加入第三方群组。收到唯一消息 ID 和截图后，目标才标记为发布已验证。验证消息不计推广成果。
5. 验证成功后直接继续自主运营，无需再次启动。Supervisor 按业务、偏好、近期内容及真实效果规划。创建或发布结果不确定时只核对，不重复创建或再次提交；暂停、接管、身份改变和恢复保护均阻止新提交。

2026-10-30 补充实号验收：通过产品命令 `POST /api/agents/{id}/telegram/bootstrap` 安排全新频道，Supervisor 和产品浏览器网关完成创建、公开设置、版本化授权、验证消息、首篇正式业务内容及回执核对。新频道为 Seka 阅读与翻译，与已有频道不同；两条新消息均有真实服务器 ID 和截图，用户浏览器接管次数为零。开发阶段修复代码并重启服务，未由 Codex 直接控制实号浏览器。结果不确定时核对原任务；仅在新频道完整可见历史只有创建服务消息且原文仍为草稿的狭窄情形，保存未生效证据后恢复同一动作。测试仍不代表媒体格式、其他账号或其余十个平台均已实号验收。

社群培育通过 `/api/agents/{id}/community-growth` 配置和关闭，`contextual_outreach` 由所有者显式启用后记录账号委托。产品 Agent 使用原生全局搜索、公开网页和一次有界的 browser-use 补充探索寻找候选，按账号委托核对群、加入、限量读历史并回应真实问题。模型短决策与浏览步骤分别保存，重启续接；已加入群每小时可回访。默认最近 30 条历史，每天最多加入 1 群、回复 2 次，每周最多推广 1 次。普通互助与商业需求分别判断，推广需要真实相关方案需求且可见群规未禁止；明确品牌/AI 身份，不私信、不采集成员名单。本轮实号已由产品完成找群、加入、读取及一条上下文回复，并在浏览器服务重启后核对同一回执；尚无外部群真实推广回执。详见 [社群策略](docs/policies/community-growth.md)。

Telegram 的文字、图片、视频网页路径均已实现；其余十个平台的格式范围、权限状态与测试边界见 [CHANNELS.md](docs/CHANNELS.md)。没有登录和授权自有测试频道之前，M3 不能标为验收完成。
