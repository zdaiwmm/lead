LEAD / HOW IT WORKS

从产品目标，持续推进到可核实的结果

Codex 根据实际证据研究、规划和执行，Lead 保存任务、账号与真实结果。研究、内容和不同账号可以独立运行；需要同一份产物的工作才等待它。

一次连接，共用服务器 Codex

服务器完成一次官方 ChatGPT 登录并启用后，新建运营 Agent 自动使用共用 Codex，无需逐项目配对或另配模型 API key。创建项目前也可直接根据官网整理产品资料。项目与工作室分别保存执行范围、会话和工具权限；共用计算设施不会共享业务授权。关闭网页后后台继续，服务器任务不依赖 Mac 在线；服务器离线时等待恢复，不自动改用 API 模型。个人设备可在项目高级设置中作为明确例外。

↓ 保留原项目与账号资料

提供产品介绍与目标

先理解产品的核心价值、适合的人群与证据。没有登录账号，也可以开始调查。

连接渠道账号

可一次提供本次登录信息，也可先检查已有登录状态。平台在原窗口核对真实身份，遇验证码、扫码或设备确认等必要步骤再请你接手。第三方登录完成后，回到原站重新核对身份。嵌入来源需确认时会显示具体网站，仅临时读取公开内容。关闭窗口后继续核对；取消连接会结束本次尝试并清除登录信息。

↓ 独立准备，有证据后继续

一个经营判断入口

Codex 根据产品、适合的人群和实际场景寻找推广渠道，再核对账号与执行条件；候选不局限于已连接的平台或已有受众。它使用实时调查、已有结果和适用经验选择下一步，保留完整会话并自动压缩长上下文。可通过原生子 Agent 并行调查，汇总后形成一致判断。内部实验和工具衔接无需用户另行编排。

↓ 分成可独立完成的工作

调查需求

优先使用 Codex 实时搜索，按需要组合公开来源、可选的 Tavily、TikHub 和通用浏览器。账号页只使用本任务已授权的账号；某个供应商或来源受阻时，其他可用来源继续。

制作内容

Codex 使用有依据的承诺和素材生成内容，按需要调用现成 Skills、插件和媒体工具。可选视频失败时，合适的文字工作仍可继续。

核对账号

按当前任务要求寻找发布或回复方法，平台独立核验当前身份、可运营位置与能力。原浏览器和账号资料继续使用，接入缺口会单独说明。

推进渠道操作

Codex 结合获准页面的结构和当前截图推进工作，工具逐项重验身份和权限。提交前核对实际身份、位置、正文和原帖；新站点先核对规则与编辑器；规则在其他页面时，查阅后回到实际编辑器继续。操作仍沿原 Action 记录。

观察实际结果

独立核对发布回执、到站与可信业务事件，识别需求、分发或产品价值的断点。执行结束与真实业务成功分别记录。

恢复受影响工作

追加要求进入原会话。设备断线或进程重启后，先核对原线程、任务和外部动作，再继续原工作；无法确认的执行保持未知，不通过换新会话或重发推进。

从陌生受众寻找机会

Telegram 可以在当前账号委托内搜索相关公开群、核对真实身份与群规、按许可加入并有限读取近期讨论。候选地址来自实际账号字段，群名中的提及不能作为访问地址；检查前再次核对来源绑定。围绕具体问题提供有依据的回复；商业介绍还需符合该群当前规则并说明品牌关联。入群申请待批准或某个目标不适合时，其他有依据的工作继续。加入结果未知只回查原申请；回复沿原 Action 保存正文与真实消息回执，避免重复发送。只有所有者在原策略入口明确选择由 Agent 决定频率时，经营频率才交给 Agent；原策略更新仍停止旧调度循环，当前经营任务使用现有项目、账号和执行控制。账号控制可停止公开群参与，旧排除项和已撤销权限继续生效。账号读取受阻时，恢复检查实际核对当前环境、登录身份及权限；通过只恢复相关读取条件，已过期任务不重跑，旧错误来源、入群与发布结果仍分别核实。

↓ 保存真实产物、回执与业务证据

事实支持下一次判断

公开搜索沿当前启用的 Codex 执行，候选页面仍需读取原文。公开网页通过受限的匿名读取通道取得，读取前后均核对原任务权限；账号页继续使用本任务的原账号。只有实际保存的原文才产生可回读的资料引用；搜索摘要、登录页和拦截页不算需求证据。来源的解析、连接或网站响应失败会保留具体原因；来源策略拒绝保留独立类别，任务权限仍逐次核对；不自动重试或放宽限制。单个来源失败不表示所有调查都不可用。读取通道本身受阻时，由平台负责修复，不能一律转为等待你补充资料。旧正文复读保留原时间，不会变成重开已耗尽路径的新依据。不借账号浏览器访问外站搜索。

内容任务完成后，可回读该任务引用的完整草稿及其版本、摘要和来源，再核对内容与下一步。版本不一致或工件不可用时保留具体缺口；草稿和声明核对不等于独立验证或发布。

实验创建未准入时，相关组整体回滚，已经接纳的其他组保留。Lead 指明被拒的实验命令、原因和同组可检出的输入错误；模型在同一次修复中可以改提不依赖实验的账号搜索或检查，继续核对当前账号权限与原来源停止条件。取得真实场所证据后，再判断实验及后续发布。没有任务在推进、模型选择停止且当前仍有声明的独立调查选项时，Lead 在同一次判断内复核停止理由；调查选项不代表执行已就绪，复核仍可保留真实等待，不增加重复唤醒，也不重做已接纳的工作。配置事实也记录当前经营判断规则版本，平台据实际配置变化唤醒下一次判断，并沿原机制去重。

复用仍适用的来源、结论和操作经验，新证据可以修正旧经验；没有经验也可继续。累计同一问题的投入。没有新学习或真实进展时，停止重复工作，选择有依据的替代路径。下一步被拒绝或无可执行路径时，保存原因、负责方、真实继续条件及条件满足后的动作。已经停止的能力检查不显示无人执行的下次检查时间；新条件也不会重置旧失败、复活过期实验或授权发布。

等待只影响相关工作

  • 一个账号登录失效、审核未结束或网页不可读，不会暂停其他独立账号和任务。执行设备离线的工作等待同一设备恢复。
  • 兼容账号共用持久浏览器，在各自固定页面并发；同站多账号、出口或登录冲突时分开。同账号一次执行一项写入，原操作的只读核对可与另一项独立写入并行。等待本人输入会释放执行槽。
  • 账号暂停、项目暂停和解除绑定作用于同一份控制状态。中断先阻止后续提交，已经发生的操作和晚到回执仍保留。恢复后重验身份，旧权限和旧命令不能复活。

结果有明确依据

  • 草稿、已提交与已确认发布分别记录。提交结果未知时，只核对原操作，避免重复发送。
  • 未接像素时按短链和点位读取有效点击，接像素后增加归因到站，接事件后增加对应转化；诊断访问与机器人单独排除。没有像素或核心价值事件不阻止继续获客。点击、到站和注册分别记录，核心价值新增仍需可信业务证据；缺少口径或历史时显示未知。
  • 成果按明确的主体、口径和窗口去重。邀请来源与直接渠道来源分别记录，测试与验收事件不计入客户成果。
  • Codex 用量、供应商费用和历史未知账目分别保留，不把 token 统计当作实际扣费。经营事实及经验来源继续由 Lead 保存；私有资料和账号权限不随经验转移。
工作台只保留产品目标、实际工作、真实结果、账号控制和必要本人事项。一次成功说明路径可能成立，仍需继续验证能否稳定带来价值。
