# 本地像素测试页

HTML、CSS、JavaScript 页面无需构建。标准库本地服务器另外提供模拟订单与支付测试接口，独立于现有产品页面。仅需静态预览时也可以使用 python3 -m http.server。

在此目录运行：

```sh
python3 server.py
```

浏览器打开 http://127.0.0.1:8787 。在像素后台将测试网站地址设为这个地址并允许对应 Origin，然后粘贴完整安装代码，选择事件发送方式并点击“应用并刷新”。也可以把代码直接放入 index.html 的 head 注释位置。

页面提供浏览商品、加购、结账、模拟浏览器支付、关联测试用户与注册、自定义事件，以及固定 event_id 的去重测试。Lead 使用仓库当前 leadq SDK，注册前调用 identify；Purchase 提供 order_id、value、currency。Activation 需要先关联用户并在 JSON 中提供后台生成的当前 rule_version。浏览器支付按钮仅模拟浏览器行为。服务端支付按钮使用本机测试订单后端：结账时保存 SDK 完整归因快照，支付时用订单原快照回传 Purchase，自动延续测试上下文。网站连接与密钥保存在项目 .state/pixel-playground.json（0600），密钥不会发给浏览器。模拟订单只允许有效格式的测试上下文，并仅向固定本机采集服务发送，不支持真实交易。

“更多事件与测试参数”可填写 lead_test / lr，也可以直接访问后台生成的带参数测试链接；所有未编辑的查询参数保留。未提供有效测试码的事件可能被后台计入正式数据。SDK 会自动缓存测试上下文；点击“结束测试”调用 leadq('endTest') 结束服务器会话并清理本地测试身份、参数与来源。后台结束测试后 SDK 会定期核对并清理，离线时联网后处理。过期会话停止上报，不会自动降级成正式流量。已保存的测试订单在结束后回传会被拒收。

Lead 记录接口返回结果；Meta、Google、TikTok 只显示 SDK 调用状态，其平台特定标准事件名与属性应按实际平台配置调整。无论何种方式，最终接收、归因和计数均以对应后台为准。不会自动放置任何第三方像素或凭据。

事件记录只存在于当前页面内存中，可导出 JSON；刷新会清空。安装代码保存在当前 Origin 的浏览器本地存储中，“移除代码”后刷新停止加载。页面不会保存真实账号或创建真实订单。

可在浏览器使用 `window.pixelPlayground.track(name, properties, {event_id})` 手动触发事件；每次操作也会派发 `pixel-playground:event` 自定义 DOM 事件，方便另行绑定。
