# 素材生产与自主运营闭环

2026-10-30。本轮覆盖 Telegram 以外十个渠道，不连接或测试真实社媒账号。

## 已实现

- **本地素材生产**：Agent 给出结构化标题、步骤卡和行动语，程序生成原创图文或带字幕的 H.264/MP4 讲解视频。按平台输出横版、方形或竖版，视频同时生成实际解码帧预览与 WebVTT 字幕。使用已有 Pillow/PyAV，不依赖用户供稿、真人出镜、付费生图或音乐服务。
- **质量和来源记录**：每个成品检查文字是否溢出、平台尺寸、图片/视频解码、真实时长和大小；记录业务档案版本、来源引用、制作版本、文本及生成声明。输出仅为讲解/示意，不伪装真实软件录像、客户案例或未执行的翻译结果。事实语义仍由业务来源和模型约束，版式检查不等于自动证明每一句营销表述正确。
- **持续制作**：模型可返回 `media_brief`；无已有素材的渠道不再被主循环跳过。制作完成后使用实际素材 ID 排入发布队列，失败记录会送入下一轮规划，供缩短内容或更换格式。重复请求复用同一制作任务并核对文件完整性。单 Agent 每日最多 30 个新制作任务、单个服务进程最多两个并发制作、单次 150 秒上限。进程中断后通过任务锁区分仍在制作与已退出的任务，恢复可安全重做的制作任务。
- **状态保护**：制作前后检查业务版本、运营配置和控制版本；暂停、归档或资料变化会阻止旧结果继续排队。临时文件清理，生成的预览、头像、封面和旧版素材不会被自动当成本轮发布素材使用。
- **账号前筹备**：已有业务档案的运行中 Agent 会自动备齐十个渠道的简介、欢迎内容、三套方案、具体选题、入口与未来排期。可在没有账号时生成实际样稿、原创字标头像及适用渠道的封面；进入某个渠道的发布计划时也会自动准备该渠道的资料素材。TikTok 的头像制作不扩张其帖子格式能力。资料素材制作失败不阻塞已有合格的日常内容。
- **确定性排期**：每渠道分别执行星期、时区、最小间隔和滚动七天上限；排队和实际执行前复查，未知提交保留容量。错过的发布日最多补一个最近窗口，避免恢复后连发。一个渠道的等待不会把其余渠道一起挂起。Telegram 与本地测试站保留原有计划节奏。
- **周复盘与策略积累**：按业务/配置/目标/方案版本保存每周观察，保留原始证据和下一步建议。只在同口径的成熟样本充分时形成暂定主方案，每五次发布保留一次挑战机会；按方案确认发布次数轮换具体选题与呈现方式。自动观察不改写用户明确偏好，不把缺失指标记成零。
- **页面查看**：工作台新增“内容与运营准备”，展示实际筹备状态、渠道筛选、成品预览和最近复盘；所有数据来自当前 Agent，保留加载、错误和空状态。

## 接口与验证

- `GET /api/agents/{aid}/operations`：筹备、最近素材与复盘。
- `POST /api/agents/{aid}/operations/prepare`：默认准备全部渠道；指定 `platform` 和 `produce_media=true` 制作无账号样稿；`profile_assets=true` 生成该渠道头像及适用封面。
- `POST /api/agents/{aid}/creative`：按结构化媒体文案生成真实素材；`GET` 同路径查看任务。
- `GET /api/agents/{aid}/creative/{job_id}/captions.vtt`：下载该任务字幕。
- `GET /api/agents/{aid}/operating-playbooks`：三套方案与目标反馈；渠道管理配置中的可选 `schedule` 由程序执行，文字节奏说明不替代该结构化字段。

本地完整媒体检查：`.venv/bin/python scripts/verify_creative_runtime.py`。会实际生成并逐帧解码 19 种平台媒体组合，报告位于 `.state/verification/creative-autonomy/report.json`。不创建发布动作、不使用账号、不调用付费模型。回归覆盖 `test_creative_autonomy`、`test_channel_calendar`、`test_operating_playbooks` 及已有素材/规划/控制测试。

本轮检查结果：常规回归 97 项通过；另启用本地浏览器专项 44 项通过，包含常规运行中因开关跳过的浏览器案例。19 种平台媒体组合实际生成并逐帧解码通过；视频采用 24 帧 H.264。前端生产构建、类型检查，以及桌面/手机无溢出、键盘展开、真实图片预览和渠道筛选通过。浏览器专项使用独立本地页面，页面查看使用明确标记的本地素材数据，不代表已在真实社媒上发布。

运行环境需要可用 TrueType 字体、PyAV 的 libx264 编码和已有媒体解码器。Linux 使用 DejaVu 与 Noto Sans CJK 字体（例如 `fonts-noto-cjk`）；macOS 使用系统字体。维护者可通过 `LEAD_CREATIVE_FONT` 指定已安装字体，用户不需要配置。CI 已加入 CJK 字体依赖。

## 留到外部条件具备时验证

真实账号身份、资料写入、平台许可、首次格式验收、主页入口和线上回执在提供账号后逐项校准；生成了头像/简介草稿不代表已修改线上资料。平台发布限制继续沿用已有能力登记。

注册、试用、付费优化依赖业务网站及服务端的真实事件回传；协议、去重和方案归因已具备，实际接入仍须在有网站部署权限的环境验收。只有社媒账号不能凭空获得另一个网站的订单数据。共享主页入口只支持渠道归因，不据发帖时间分给某篇内容。缺少回传时继续有计划地探索，不编造转化结果。
