# 真人验证与原窗口接管

账号浏览器遇到可识别的真人验证时，保存验证状态，保留当前浏览器会话与页面，通知用户处理。验证码不会由模型自动填写或绕过。

## 用户流程

1. 社媒账号显示「等待真人验证」，工作记录和对话同步提示。
2. 点击「打开原窗口验证」。复用原会话，不跳转平台首页、不清除登录资料。
3. 用户在原窗口完成验证及平台要求的继续步骤，返回已登录页面。
4. 点击「验证完成，继续任务」。系统重新检查验证页面是否消失、登录账号是否与原任务一致。
5. 原授权与运行状态未变化时，恢复原任务。已经提交但结果不确定的动作只核对回执，不重新提交。

关闭接管窗口或接管过期不会清除验证状态，也不会恢复自动操作。可重新打开原窗口。用户主动暂停、关闭渠道或更改配置／授权后，完成验证不会覆盖这些决定。

## 实现与边界

- 检测依据包括可见的 CAPTCHA／Cloudflare／Arkose 验证组件、专用验证页面标题与路径。隐藏组件和文章内提及验证的标题不作为证据。普通登录失效仍使用原登录流程。
- 状态存入 Agent 的 `onboarding_state.browser_challenges`，按浏览器资料 ID 保存验证 ID、账号绑定版本、原会话 ID 和控制／配置／授权版本；不保存验证码内容、密码或挑战令牌。无需新增数据库迁移。
- 当前主线按账号分配独立浏览器资料。等待验证只阻止对应资料的自动操作；仍共用旧默认资料的账号一起等待，独立资料及其他 Agent 不受影响。
- 浏览器闲置回收会保留待验证会话；已排队的浏览器操作取得锁后仍需再次检查验证状态。人工操作沿用原接管令牌与权限校验。
- 验证完成通过同一数据库事务解除等待并写入恢复事件。恢复沿用原任务、动作和幂等标识；重复完成请求不重复安排任务。
- Reddit 提交前另开规则页时，若该页要求真人验证，接管展示这一个原标签页并保留已填草稿。核验通过后返回原草稿，再检查社区规则；草稿页丢失时继续暂停。
- 确认尚未编辑草稿时可重新准备。已经部分上传或编辑、但缺少可恢复检查点的草稿，仍要求核对原草稿，不以「验证通过」为由自动重建。
- 浏览器进程退出或原会话丢失时，不能声称原窗口仍存在，也不能自动恢复发布；保持等待并显示窗口失效。此时需另行恢复账号连接并核对原任务。解绑账号会取消该账号的验证等待，并沿用既有任务取消及回执保留规则。
- 站点改版或新的验证供应商可能需要补充检测规则。当前验证不代表 Reddit、X 实号已完成验收。

## 验证

`tests/test_browser_challenges.py` 使用隔离测试 Agent、数据库与受控浏览器页面，覆盖检测误报、重复通知、原页保留、并发等待、重复完成、账号切换、控制版本变化、窗口丢失，以及提交前／提交后的恢复。

```sh
LEAD_BROWSER_TESTS=1 .venv/bin/python -m pytest tests/test_browser_challenges.py -q
```

测试不会登录真实社媒账号，也不会向真实平台发布内容。
