# 阅读与翻译社群培育策略

2026-10-30。业务：Seka。用户授权产品探索相关社群、读取可访问历史、提供有用互动，并在需求匹配时介绍产品。

## 产品当前执行范围

常驻 Agent 可周期研究站外公开介绍和规则，保存候选的真实页面证据。配置入口是 `/api/agents/{id}/community-growth`，可控制主题、研究间隔、每轮候选数和未来参与限额。默认一天研究一次，每轮最多五个候选。

找群默认在上一轮完成 24 小时后自动开启下一轮，不需要新的聊天消息或再次点击研究。已加入且仍有成员身份的群每小时回访；失去成员身份或明确禁止自动化的群停止周期回访。社群到期时间与自有频道发帖时间分别计算，运行中的后台至少每五分钟检查一次状态并更新心跳。接口返回 `schedule`，包含下次找群、回访与后台检查时间；这些时间由产品的持久工作流执行。临时模型断连会保存重试时间，已提交动作仍只核对、不重复发送。

公开网页研究使用独立、无登录状态的环境，不访问 Telegram 消息聚合站。启用社群委托后，产品还通过已连接账号的 Telegram 原生全局搜索寻找公开群，只收集群名、公开链接、群编号和成员数等候选元数据。候选链接必须来自实际页面证据，模型不能编造社群或自行授予能力；进入后再核对可加入、可读、可发言状态。

当前搜索方向收窄到长文或 EPUB 全文翻译、术语一致性、多语言作品协作。每轮先规划具体需求的查询，再核对公开入口及账号可见群；明确需求的网页查询和后续入口保留独立的有限容量，不被通用导航占满。一批候选完成普通帮助后，仍继续本轮剩余搜索与调整方向；只有尚有正在执行或回执不明的操作时才暂缓。普通阅读器推荐和设备排障不能记为 Seka 推广机会。

公开搜索引擎实际无结果或出现验证页时，产品可改读公开项目仓库和维护者社区入口；不绕过验证。仓库搜索页面中实际出现的相关项目链接会进入有限续查队列，不只查看第一个项目。入口旁的 Group、Contact 或 Channel 标签与上下文一起保留，避免把个人联系人或广播频道当成讨论群。外部来源只能帮助选择检索词；尚未加入的公开群仍需从账号有权访问的本群历史核实实际需求，不能凭项目介绍推断群内存在营销机会。

每轮补充公开探索最多三次，依次调整 EPUB 翻译、PDF 翻译、双语电子书的仓库查询，并把已经实际核对过的项目链接带给下一次探索，减少重复。每次最多查看五个公开页面；这不增加社交账号加入或回复额度。中断的探索保留已消耗次数，不重放同一次执行；后续探索另记一次，达到上限后回到下一次定时发现。

用户明确授权后可启用 contextual_outreach 策略，记录与稳定账号绑定的社群委托及账号风控风险接受。产品依次研究候选、核对公开群身份、加入、限量读取近期历史、判断需求并回复；只有真实问题询问相关方案且可见群规未禁止相关产品问答时才介绍产品。加入和回复都有提交前持久记录，回执不明时只核对。模型决策使用无隐藏网络重试的短请求；找群和页面进度分步保存，重启可续接。

社群关联性和发言时机使用不同的模型决策：尚未加入时只判断真实关联和明确禁令，不生成回复或判断推广许可。简介或实际讨论能证明与阅读、文献、笔记或翻译工作流相关时，可先加入观察；阅读器 TTS、FB2/EPUB 排版等技术讨论也属于阅读体验。没有未回答的问题就不发言。仅有相似群名或用户名不能证明关联。回访先通过原生控件回到最新消息，再决定是否需要群内搜索；不把旧搜索位置当成最新讨论。新策略重新评估时沿用已有成员记录，已失去的成员身份不会自动重复申请。

需要管理员批准的公开群使用原生申请入口，提交前保存同一动作记录，核对原生“取消申请／等待审批”状态后记为待审批，不能记成已加入。申请结果未确认和已确认待审批分别记录，两者每十五分钟由产品定时只读回访，期间继续其他社群搜索；不重复提交或取消申请。原申请消失而成员身份仍未确认时停止自动申请，保留真实阻塞原因。后台投递按工作区隔离失败退避，避免失效工作区拖累正常运营；因并发或运行时段暂缓时也更新心跳及下次检查时间，不绕过原有运行门槛。

入群动作先退出群内搜索、确认当前群范围，再点击唯一原生按钮；容器中存在唯一按钮时操作按钮本身。申请点击未被接受的续接与回执不明后的重发分开：此前记录明确未加入且申请入口仍在，超过一分钟，再刷新账号原生群状态确认同一账号、同一群、仍可申请、没有待审批状态或弹窗时，才允许继续原申请一次。续接前保存刷新证明和次数，不能重新生成任务或清除原提交记录；已有待审批或成员身份就只核对，证据不足或已续接过则保持只读。

点击发送不等于消息送达。回执缺失时保留原文与原消息指纹，先核对；只有连续观察确认原草稿仍完整保留、已过一分钟、服务端最新消息编号未推进、群范围搜索无正文且原问题和回复指向均未变化时，才允许通过原生键盘继续同一草稿一次。继续前先持久记录证据与次数；已出现正文、消息编号推进或证据不足时不能再次提交。此路径不重新生成内容，不改变推广与频率门槛。

实号验收已有原生找群、多次加入提交和可访问群历史读取记录；其中一个群后续失去成员身份，不能把加入按钮点击当成持续可运营。产品 Agent 在 Arabic/English language exchange 群回应了一条真实 Fusha 语伴求助，回复回执为 `-2074101136:4295127186`；浏览器服务重启后仍核对同一回执，未重复发送。新增 Zotero Russia 已确认加入并核对文献与笔记讨论；Librera Community 已确认加入，并回应真实 TTS 快捷启动问题，回执为 `-1838711851:4294971439`。Librera 首次鼠标尝试没有消费草稿，产品在确认原草稿、消息编号与群内搜索结果后通过原生键盘完成一次，最终只出现一个对应回执。产品随后自行加入 FBReader Chat Room，回应真实 PDF 阅读器求助并核对回执 `-1246167968:4295001923`。这些回复均为非商业帮助，不含产品链接；Librera 与 FBReader 两条新回复均无 AI 身份开场。KOReader、Librera、FBReader 等阅读器讨论群已有真实读取或回访记录，未匹配的技术支持问题与已充分回答的话题均未插入推广。外部群真实推广仍无回执，不能把普通回复计为推广验收。隔离测试覆盖加入防重、群范围搜索、定期回访、原消息定位、临时编号、发送回执丢失后的核对、未被接受的草稿继续一次、论坛消息视图与搜索跳转地址识别，不能替代实号发送证据。

## 持续经营

1. 账号和官方频道：使用真实品牌介绍；围绕长文/EPUB 阅读、术语一致性、翻译协作发布经业务资料支持的内容。按内容需要发送，不把凑日更当目标。
2. 发现：从原生公开群搜索、独立官网、维护者页面和规则页寻找原版阅读、翻译、读书讨论的相关社群。搜索词由 Agent 根据真实候选结果调整。区分广播频道、讨论群和频道关联讨论区。排除禁止自动化、以资源侵权分发为主的目标；群规禁止推广时不进行商业介绍。
3. 范围：用户在 2026-10-30 明确要求自动找群、读群历史并按需营销，承担账号风控风险。产品保存该账号委托，限于账号有权访问的公开社群，遵守群内明确的参与限制。不采集成员名单、不读取私信，不批量导出或建立群历史资料库。每轮默认仅处理最近 30 条已显示的文字，最多可配置 100 条，原始历史不持久化；持久记录仅保存目标、选中问题的摘要哈希、回复内容与结果。账号风险接受不代表取得第三方内容的所有权。
4. 互动：在账号可访问且群规未禁止的讨论场景，回应明确的阅读或翻译问题。在已加入的相关社群，也可针对真实语言学习、语伴协作或互助问题提供具体非商业帮助，不要求每次互动都有产品需求；这不能扩大加入范围或放松推广条件。先给可执行的答案；不为了活跃而插话，不自动私信陌生人，不跨群复制回复。
5. 介绍产品：对方明确询问相关方案，且社群允许商业参与时，结合具体困难介绍已确认的 Seka 功能，说明品牌关联；不虚构使用经历、客户评价、收益或效果。拒绝后停止，不重复追问或追加链接。
6. 回访与复盘：已加入群每小时可再次观察，必要时在经过群范围核对的原生搜索中寻找相关问题；每次仍受历史条数限制。不重复回应同一群的同一原消息，也不跨群重复文案。旧任务的发送回执保持原样，回访创建新任务。有负面反馈或规则变化就停止。阅读量和成员数不能直接记成转化；缺少回传时不声称产生效果。

## 自然表达

写短句，围绕对方的具体问题，必要时只问一个关键澄清问题。首次参与与后续回复都不主动添加“AI community assistant”“AI 助手”或“自动化运营账号”等身份开场；不堆功能、不用夸张承诺、不自动塞链接。商业介绍清楚说明与 Seka 的品牌关联。被直接问到是否自动化时如实回答；不声称自己是真人、不虚构人员身份、亲身经历或独立用户评价。

示例：问题涉及 EPUB 术语前后不一致时，直接解释如何建立术语表、记录译名与检查一致性。如果对方继续询问合适工具，可说明“我负责 Seka 的社群运营。Seka 提供术语表与 EPUB 翻译，可以按你的术语要求处理”，并只补充官网已证实的信息。

## 参与门槛

候选发现 → 核对相关性及群规 → 验证公开群身份 → 按账号委托加入 → 限量读取历史 → 找到尚未充分回答的相关问题 → 有用回复 → 对方询问且允许商业参与时介绍产品。禁止自动化或目标不明时停止；推广条件不足时允许只提供帮助或不发言。

产品默认限额：每天最多加入一个社群、回复两次，每周最多一次商业介绍。用户在 2026-10-30 将当前账号策略的每日加入和回复上限均调整为 100 次，商业介绍仍为每周一次；配置可随时调整或关闭，每次参与仍须先通过以上门槛。额度是上限，不是发送目标，也不是 Telegram 官方认可的安全阈值。没有符合条件的机会可以零发送。不使用模拟真人的随机操作、绕验证或规避限制的策略。
