# Lead 小修复交付

2026-11-11 用户确认：一次授权、一个 PR、一次与范围匹配的完整验证、发布同一份产物。新任务采用本规则；在途检查、冻结候选、部署请求和已加载工具继续原协议，不取消、迁移或改发。

## 固定流程

1. 核对仓库、GitHub main、线上版本与在途发布。从最新核实基线在独立目录开工，保留共享目录内容。先查真实安装/取件入口和调用方，再改代码。
2. 一个故障对应一个 PR，列出范围、必要依赖、排除项与消费者，本地定向验证。独立交付正常建 PR，不默认草稿，不追逐无关 main 更新。
3. PR 快速检查：静态/凭据扫描、范围与放行契约测试；应用改动补类型检查。Agent 核对精确 head 成功后合并。当前仓库没有 main 分支保护，执行时必须实际核对结果。
4. 完整验证仅在合并后的精确 main 执行。失败阻止该候选发布，不回退旧绿；其他已验证候选仍按其原授权交付。
5. 复用同一 SHA、成功 run/attempt 的产物，不在发布时重测重建。核对生产到候选累计差异，未授权功能移出本批或重新确认。
6. 工具安装、应用切换、独立回读分别记证据。结果未知先回读，已切换只续回读/回传，不盲目再发。文档收尾与已核验成功分开报告。

## 验证范围

| 范围 | PR | 合并后的完整验证与产物 |
| --- | --- | --- |
| 登记工程文档 | 快速检查 | 格式/凭据与范围契约；无部署包 |
| 登记维护工具、测试及 CI | 快速检查 | 工具安全回归、真实 Linux 挂载/恢复及工具锁/回退/中断演练；独立工具包 |
| 应用、未知或混合变更 | 快速检查与类型检查 | 原数据库、媒体、权限、浏览器、隔离、前端构建及 Linux 演练；应用镜像，含工具变化时另出工具包 |

范围由 scripts/ci_scope.py 的显式路径与 Git 文件模式决定，不接受标签或“只是工具”声明。main 比较整个 push 前后差异。未知路径、非普通文件、代码删除、缺历史、手动派发回退应用全量。产品/安全契约、数据库、依赖、隔离配置及未登记工具不走捷径。修改 CI 本身也必须通过契约回归。

应用放行要求最新精确 main 成功、backend/frontend/namespace 完成和 Application verification 证明。工具要求 Tool verification（或完整应用证明）、Linux 演练与工具包构建成功。PR、文档、跳过、失败、取消、旧 attempt 均不能冒充发布证明。旧应用 CI 协议保留，但不能证明新工具包。

开发本地按故障与直接消费者验证，成功证据在输入/环境未变时引用；范围、依赖或环境变化、新失败时重验。本轮先登记已核实的工具，应用在 main 保持全量，后续专项另需覆盖依据。

## 授权与并行

用户明确说“修复并上线”“合并发布”或确认包含交付的方案后，Agent 连续完成已授权需求/环境的交付并记录精确 SHA，不要求用户再复述哈希。额外功能、权限扩大、数据迁移和环境变化重新确认。纯调查不授权写入。GitHub 环境保护不删除、不绕过；已授权且具备权限的操作者可办理本次审核。

冻结后新功能进入下一批。已有候选不追逐 main。存在其他发布不代表独立代码不能合并；仅在会取消检查、改变候选、争用同一锁或替换仍在使用的工具时等待具体冲突。业务任务、接管、未知动作仍由原维护入口核验，不强清账本或关闭用户窗口。

## 正式工具入口

维护电脑从已授权范围内的精确 main 检查工具包：

```sh
python3 scripts/tool_release.py <完整SHA> --tool home_systemd_release.py
```

已授权安装时使用既有 SSH 和私有证据文件：

```sh
python3 scripts/tool_release.py <完整SHA> --tool home_systemd_release.py --install --ssh-config <已有配置> --host <目标别名> --receipt <私有证据文件>
```

工具包为 lead-tools-<SHA>-<attempt>。校验最新 main 的证明类型、同轮产物、有效期、GitHub ZIP 摘要、清单及源文件摘要，取件后再核对 CI/产物。服务器持有 deploy.lock，核对旧工具和应用未漂移，检查 main Git 来源，备份并记录原字节，原子替换一个文件；失败按已知字节回退。中断保留原始身份，已安装则只核验，不重复写入。另起 SSH/Python 进程独立回读。

仅允许登记的现有工具；首次置备另有明确方案。一次只更新一个工具，不宣称多文件具有事务性；协议依赖变化需明确顺序与恢复边界。应用镜像不安装或执行工具源码，所以工具源码变化不再要求手改服务器摘要白名单；未知 scripts、运行依赖、数据库和主机配置仍走原兼容核验。

## 应用取件缓存

```sh
python3 scripts/prepare_home_image.py <完整应用SHA> <私有暂存目录> --archive-only --cache-dir <私有共享缓存目录>
```

输出 revision_verified: false 只证明 ZIP，节点仍核验归档、REVISION、镜像和挂载。完整 Linux 准备模式不加 --archive-only。工具/docs 绿色 CI 不能下载应用镜像。每次缓存命中仍核验最新 CI、来源、有效期和摘要；默认不启用缓存，满额普通下载且不删其他版本。

## 耗时验收

分别记录本地验证、PR、main、取件、维护等待、安装/切换、回读及文档。排队和网络计入总耗时并单列。工具交付必须证明没有启动业务全量，完整工具验证仅在 main 一次；Linux 故障演练和来源、权限、锁、回退检查保留。用实际交付时间验收，不把单测或缓存秒数当成整体发布时间。
