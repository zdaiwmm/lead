# Lead 小修复交付

适用于本规则合入后新开始的任务。正在进行的发布保持原候选、审批、请求 ID、节点工具和验证要求，不取消检查、不重派发布、不自动换候选。工程交付的优化不改变产品 Agent 的社媒发布权限、调度或回执语义。

## 从修复到可发布版本

1. 核对 GitHub main、当前线上版本及相关在途任务。在独立任务目录从已核实的 main 开工；旧脏目录只用于提取明确归属的补丁，不把它整体当作发布源，不移动或提交其他任务的内容。
2. 在需求记录列出故障、受影响入口与直接调用方、成功/失败/重试用例，以及本批纳入、必要依赖和明确排除项。小修复以一个明确故障为范围，不用文件数判断风险。
3. 开发中运行受影响的本地验证。修复稳定后冻结任务提交，提交 PR；本地验证可与 PR CI 并行，但所有必需检查通过前不合并。PR 推送更新自动触发检查，不再额外手动派发同一候选。没有 PR 的任务分支推送不运行 CI；需要远端验证时创建草稿 PR。
4. 冻结后不因无关 main 前进重建候选；确有依赖、冲突或影响本次行为的变化才重新集成和验证。当前生产到候选的累计变化也必须核对：main 已含其他功能时，如实列入范围，不能把整批称作仅有一个修复。
5. PR 全部必需检查成功后正常合并，等待该合并 SHA 的最新完整主线 CI，并复用同次构建镜像。保留精确版本与目标环境的生产确认。按 HOME_RELEASE 的原入口切换、独立核验与回报。

## 验证分工

| 影响 | 本地验证 | 远端与上线 |
| --- | --- | --- |
| 纯工程文档 | 链接、差异、仓库凭据检查；不启动数据库或浏览器 | PR 和 main 现有必需检查仍保留；不因文档变化重新发布应用 |
| 能界定影响的呈现或单一功能修复 | 静态检查、故障回归、直接消费者与异常/重试路径；前端修改补类型检查、构建及受影响浏览器操作 | PR 和精确 main 的 backend、frontend、namespace 均须完整通过 |
| 权限、身份、租户隔离、凭据、网络隔离、数据库/迁移、持久化、暂停/接管、外部动作去重、恢复、发布工具，或影响不明 | 对应安全/恢复专项及必要集成环境；不能仅凭小补丁降级。发布工具使用隔离夹具，系统挂载/恢复等 Linux 证据由完整 CI 提供 | 原完整检查与上线门禁全部保留；真实环境缺口单独记录 |

记录命令、源码提交、工作目录、环境、结果及未验证项。同一源码、同一命令和同一环境已经通过且没有新风险时，引用原证据，不为了重复汇报再跑一次。源码、测试、依赖、环境变化或存在较新失败时重新验证；不跨任务、跨环境或跨命令推断覆盖。完整 CI 成功不能替代实号验收，本地专项成功不能替代完整 CI。本轮不实施云端测试裁剪。

CI 的触发职责：任务分支由 pull_request 执行完整检查；main push 执行完整检查和精确镜像打包；显式 workflow_dispatch 仍完整执行。没有新增取消策略，不取消已有运行。PR CI 不冒充 main CI。

## 提前准备与固定批次

在本地/PR 检查期间先只读盘点线上临时代码覆盖、必要配置、活跃接管、未知外部动作、备份与原发布请求状态。复用发布节点已有的 current、维护状态和回执查询入口，不新建生产写入。发现未入库的必要线上修复时，先固定它的来源和依赖，交由获授权的任务完成 PR；不能在已下载安装包之后才第一次查版本差异。

主线 CI 完整成功后，可用既有 prepare_home_image.py 提前准备精确 SHA 镜像。取件不暂停业务、不获取发布锁、不登记部署、不修改 current，也不授予生产切换权限。检查到业务正忙时记录阻塞，直到获准的维护窗口再由原入口排空；不为了“加速”丢弃未知动作或踢出用户接管。

固定本批后，新功能和无关修复进入下一批。只有保证当前生产功能不被覆盖的必要依赖、同一故障的阻断修复才加入；加入后重新列出差异、验证、候选与生产确认。其他任务已经在发布时，不抢发布锁、不合入会迫使它重新集成的改动；本任务保留草稿 PR，待其发布收尾后再核对主线与安排交付。

## 发布包缓存（按需启用）

在受信任父目录中，为下载身份建立私有暂存与缓存目录，再从审阅后的工具版本执行：

```sh
python3 scripts/prepare_home_image.py <完整SHA> <私有暂存目录> --cache-dir <私有缓存目录>
```

缓存存储 GitHub 原始 ZIP，以产物 ID 和认证摘要区分；每次仍在线核验精确 main 的最新 CI、run/attempt、产物归属、大小、有效期及摘要。缓存命中后逐字节重新校验，再核对镜像内 REVISION，完成前复核 CI 和产物身份。篡改、过期、新失败、新 attempt 或身份不明都不会用旧缓存放行。缓存不是发布证明，也不替代节点 root 校验、备份、维护锁与独立回读。

不传 --cache-dir 时保留原来的每次下载方式。缓存是本机下载优化，不减少首次下载或节点间传输；不把已有暂存镜像当作可信来源。每次写入前以 4 GiB 为容量上限检查，达到上限时本次沿用普通下载，不自动删除其他版本。多个准备进程可安全写入同一摘要，额度检查不是跨进程磁盘配额；用专用目录并由维护者在没有使用时清理。缓存不保存凭据。现有生产节点不会自动安装或启用新工具，安装另走原 PR/CI 与主机维护流程。

## 失败续跑与完成时间

- CI 失败：定位失败，修复后只等待新的候选检查；不回退到同 SHA 的旧成功记录。
- 发布开始前失败：修复明确阻塞，重新核对原请求是否已开始，不盲建重复请求。
- 切换已开始或结果未知：先独立核验与恢复原请求，不能再切换一次试运气。
- 独立核验已成功、状态回传失败：只补回传；记录整理失败只继续整理，不重新发布。

分别记录本地验证、PR CI、main CI、取件、维护等待、切换、独立核验和文档收尾的实际时间。独立核验通过立即报告“已上线”；文档收尾另报完成状态。真实社媒业务回执另行验收，不把服务上线当作推广成功。未测量前不承诺固定发布分钟数。
