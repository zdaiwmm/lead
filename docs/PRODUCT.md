# Product

## Register

product

## Users

运营小白、小团队创始人和产品负责人。用户提供产品介绍、目标和账号，让产品自身持续推进运营，通过真实结果决定是否继续投入。用户不负责提示词、工作流排期或日常任务编排。

## Product Purpose

以最少功能完成“理解产品 → 选择有边界的验证 → 独立执行 → 核对结果 → 纠正下一步”。每个项目只有一个经营判断入口。研究、内容、账号、渠道、观察和恢复由持久任务推进，跨项目和独立账号可以并行。

保留五类用户信息：产品与目标、实际工作、真实结果、账号控制、必要本人事项。移除日计划、周计划、固定轮换及重复启动/授权步骤。登录完成后自动核对当前身份和实际可执行范围；既有暂停不会被重新登录覆盖。

本轮规范和实施边界以 [自主运营运行时 V2](requirements/20261112-autonomous-growth-runtime.md) 为准；代码实现、生产切换和真实获客分别验收，文档更新不代表已发布。

## Brand Personality

简约、清楚、可靠。沿用已确认的石墨暗色、珊瑚操作、紫罗兰数据和薄荷状态。模块之间有宽松间距，低频操作放入弹窗，正常运行保持安静。产品名为 lead。

## Anti-references

避免技术控制台、模型参数主屏、日志堆砌、多层卡片、默认日历、强制规划表，以及账号登录后还要求逐级批准的操作链。

## 自主推进契约

- 新项目已有网址或介绍即可开始产品资料调查，不等待账号、激活埋点或发布位置。其他账号可以同时连接。
- 经营判断在产品内部完成。外部 Codex、人工制定渠道方案或额外定时任务不构成日常运行依赖。
- 先判断实际断点，再选择能够验证它的最短工作。实验是内部记录，不要求用户维护实验管理流程。
- 每项工作有明确产物、观察期限和有限投入。只等待真实需要的引用产物；一个网页、账号、模型调用或审核不会成为所有工作的屏障。
- 用户暂停、撤销或归档继续生效。未知外部提交保留原动作身份，只核对原提交；不通过重建任务、换标题或重发制造进展。
- 故障尝试累计，耗尽后只做有边界的条件探测。相关条件恢复后继续原任务，无关健康信号不能清除故障。
- 生成内容、确认发布、触达、到站、可信新增核心价值使用分别记录。点击不替代产品价值目标；缺少观测和新客口径时保持未知。
- 有效产物可以复用。重复证据、改写结论、心跳和仅换时间不算新的学习。成熟复核无进展时停止该路径或选择有依据的替代。
- 工具接入缺口由产品明确承担；验证码、真实身份歧义等本人条件明确交给本人。不能把缺能力包装成用户缺授权。

## Design Principles

1. 首屏回答目标、正在推进的实际工作与可信结果。对话用于补充信息和调整方向。
2. 创建只收集必要产品资料；账号连接与初始调查独立，进入工作台无需额外“免费启动”。
3. 账号控制作用于选中的具体账号。连接、运营意图、真实权限和适配能力分别表达，避免把“已连接”写成“可发布”。
4. 需要本人处理的事项集中展示。普通研究、内容和状态读取不增加审批。
5. 查看状态和证据不会派活。工作记录可打开来源、产物与原回执，默认界面不暴露原始 JSON 或内部日志。
6. 保持桌面、窄屏和键盘可操作。编辑与证据详情使用独立弹窗，焦点正确进入和返回。
7. 本地页面合约与合成测试不能提升实号能力；真实运营和真实新增分别记录证据。

## 运行条件

本地电脑休眠、关机或常驻服务不可用时不能执行。持久运行由数据库与 Temporal 支持，浏览器执行器只执行明确操作。常驻节点、实际平台条件、模型服务、业务事件接入与费用约束仍须逐项核实。短时回归和时间跳跃证明工程行为，不能替代真实持续运行或商业效果。
