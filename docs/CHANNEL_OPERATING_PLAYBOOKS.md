# Agent 从零运营手册：Telegram 以外的十个渠道

版本：2026-10-30.v1。业务实例：Seka。状态：30 套运营底稿、本地素材生产、渠道排期与周复盘已接入；真实账号执行仍须满足现有渠道条件。本手册不改变当前 Telegram 的方案、账号或运行状态。

## 运营承诺与用户分工

用户已有业务介绍和网址，只需提供要使用的账号并完成本人登录、安全验证及平台必要的声明。Agent 负责业务研究、受众拆分、定位草稿、选题、文案、素材脚本、排期、发布核对和复盘。用户不需要每天选题、写稿、剪片、配提示词或分派任务。

业务事实沿用现有档案，不从账号外观猜测产品。若真正缺少不能从官网或既有资料取得的必要事实，Agent 一次只提出一个具体问题；不把日常内容工作转交用户。涉及金额的广告、付费素材和额外工具不在首轮预算内，默认不花费这些费用。

“只提供账号”是完整产品要达到的体验。当前已实现原创步骤图、字幕讲解视频、预览与字幕、头像/适用封面制作，以及确定性排期与每周观察记录；账号资料写入、评论互动与原生数据读取仍需对应账号能力校准。没有实际执行与回执的步骤保留待执行状态，不能向用户报告已经完成。X、LinkedIn 及其他待核对的平台条件继续沿用 [现有渠道记录](policies/CHANNEL_REVIEW.md)。本次不启动任何真实发布、不购买流量、不改变发布权限。

## 从第零天开始的统一操作流程

### 第 0 天：先完成可以独立完成的筹备

1. Agent 读取现有业务档案、官网和已确认偏好，产出一页业务事实表：产品、目标任务、可用功能、限制、真实入口、证据日期。价格与支持范围以真实流程为准。
2. 拆出三种需求状态：正在找方法、正在验证能力、即将开始但有顾虑。每个渠道的 A/B/C 是三个独立假设，不能只是同一文案换标题。
3. 准备每渠道三套方案各六个选题、至少一篇完整稿和所需素材清单；文案只使用已确认事实，视频必须区分分镜、实际画面与真实输出。
4. 准备头像、封面、简介、入门说明草稿。原账号已有有效品牌资产时优先沿用；创建、编辑或置顶只有对应执行能力可用时才提交，不能假称已装修完毕。
5. 设置本轮目标：暂定注册 `signup`；已有明确业务目标时固定为 `lead`、`trial` 或 `purchase` 中一个。整个比较周期不因结果好坏切换目标，未定义的业务完成动作不能直接等同试用。

### 第 1–2 天：账号交接与通路检查

1. 用户完成本人登录和必要安全验证；Agent 记录账号、地区、语言、自有目标及当前可用格式，不收集用户个人联系人。
2. 核对当前平台与执行方式适用范围、目标管理权限、首次格式验证和发布声明。条件未满足时继续完成草稿及素材筹备，不打开受限能力。
3. 检查一次完整承接：内容入口 → 真实目标页 → 用户能开始的任务 → 可观测事件。外链不可点击、目标不存在或需要额外资格时记录断点。
4. 独立单帖链接绑定方案；主页共享入口仅作渠道归因。不得按“访问发生在某帖发布后”就判给该帖；未经过方案链接的访问不能参加方案胜负判断。
5. 把网站访问回传、服务端转化回传、成功接收时间分别记录。只有账号时可准备和运营内容；没有业务网站事件就不能承诺精确注册、付费归因。

### 第 3–7 天：小批量启动

按平台的**总频次**轮换 A/B/C，每次只发布一篇独立有用的内容；首批依次取各方案第一个选题。没有账号历史数据时，以目标受众当地 12:00、19:00 为待验证时段；这是排期假设，不是最佳时段结论。用户明确的地区、语言、禁发时间优先。

周一 A、周三 B、周五 C；次周轮换为 B/C/A，第三周 C/A/B。每周六篇的平台在周二、周四、周六补同样顺序的第二篇；不额外叠加促销帖。YouTube 使用单独的低频三周轮换，不能为了首月比较把视频量硬加到九条。

每篇提交后核对作者、目标、链接/内容 ID 和回执；结果未知则先核对、不重复点击。记录方案、选题、开头、格式、行动语、实际目标链接、业务版本和执行结果。没有素材时可以继续准备该方案，但不能复用无关素材凑数。

### 第 8–30 天：轮换与修复

1. 每天一次检查工作失败、链接可用性、回传是否中断和待处理账号问题；暂停的渠道不因复盘自动恢复。
2. 每周一次汇总：发了什么、哪些窗口已成熟、每方案有效访问与固定目标完成会话数、观察到的承接问题、下一周只改什么。
3. 每套方案至少积累三篇成熟内容；YouTube/Pinterest 的单篇观察期为 14 天，其他平台 7 天。发布后即刻的零值不能作为失败证据。
4. 每次只调整一个有意义的变量：开头、场景、呈现方式或行动语。跨方案本身有内容差异，因此观察结果不是随机对照实验，不能声称提升由某个变量造成。
5. 访问少：核对分发与入口；访问多但有效访问少：核对标题和内容是否匹配；有效访问多但注册少：检查入口、条件与产品开始路径；注册多但实际使用未知：继续保留未知。

### 第 31–90 天：沉淀渠道自己的做法

能够区分三方案且具备可比样本后，保留表现更好的方案作为暂定主方案；每五次确认发布留一次给挑战方案。每周复盘时保留其依据，不因一篇突增永久改变定位。业务、偏好或方案版本变化后重新建立观察批次，旧结果保留供查看，不直接混入新版本。

没有达到门槛的渠道继续均衡轮换，不设“30 天必须找到赢家”的承诺。长期零访问时优先检查入口与受众来源；WhatsApp 新频道、自有 Reddit 新社区尤其不能把“发布内容”当成首批用户来源。已有官网添加订阅入口可列为具体任务，但只有获得网站修改能力与授权后才执行。

## 素材由 Agent 负责的执行规范

纯文字渠道先用事实清楚的文字启动。图文由已确认事实生成清单、步骤图和条件卡；视频采用原创字幕讲解、真实操作录屏或明确标注的流程示意，不依赖用户拍摄或真人出镜。当前引擎可把结构化文案实际制作成图文与字幕讲解视频，完成平台尺寸适配、解码检查、预览、字幕和入库。讲解视频不冒充操作录像；没有真实录屏时不声称已经演示软件操作。

每份素材交付需要：来源与使用依据、事实核对、可读性/裁切检查、实际解码、平台格式校验、必要 AI/商业声明、入库 ID。未经实际演示不能写出结果和耗时；不能伪造客户截图、评论、创始人经历、项目活跃度或翻译质量数字。付费生成服务不能因计划需要就自动购买。

## 如何按转化取舍方案

主要指标只取一个固定业务事件的**完成会话率**：观察期内至少一次服务端确认的目标事件的会话数 ÷ 同期经单篇方案链接进入的站内会话数。同一会话重复上报两次 `signup` 只计一次；`lead`、`signup`、`trial`、`purchase` 不混加。该口径是会话，不宣称为去重客户或收入。现有付费回传没有完整金额支持时，只能报告付费事件，不能报告营收或 ROI。

两个诊断量是可归因站内会话和其中的有效访问。重定向点击单列，机器人/预览排除；未接入曝光、观看、收藏或主页访问就保持未知，不能计算点击率或完播率。有效访问沿用产品现有规则，不改口径来争取更好看结果。

暂定取舍门槛：三方案每套至少三篇成熟帖子、每套至少 100 个可归因会话、三套合计至少 5 个固定目标完成会话、网站与服务端回传当前有效且接入早于观察批次。这些是初始决策参数，不是增长目标、样本量保证或行业基准。只比较同一目标、同一业务版本、配置版本、方案版本与最近 90 天的发布批次；每篇使用固定 7/14 天窗口，排除验证帖子、未确认发布和窗口未满内容。

只有领先方案的 Wilson 区间下界超过另两套的上界时才暂时增加权重，仍不称统计上证明有效；该启发式没有处理随机分组、多次查看、多重比较或按人去重。当前在线状态不能证明历史每分钟完整回传，发现采集中断或平台限制变化应重建观察批次。没有区分单帖入口、样本不足、回传中断或三方案无法都执行时，保留均衡探索。

两个运行约束优先于效果：账号/目标出现限制或权限撤回时停止相应执行；内容重复、事实失效或预算不足时先修正/减少工作，不用提高频率补数据。不触发未经授权的私信、加人、群发或广告。

## Seka 本轮业务实例

实例从现有业务档案出发，并于 2026-10-30 核对 [Seka 官网](https://seka.one)、[Translate](https://seka.one/translate)、[Collab Project](https://seka.one/translation_project) 和 [Hub](https://seka.one/hub)。具体选题围绕长文准备、术语与风格设置、协作项目条件及阅读笔记；不承诺翻译准确率、固定报价或自动获得项目支持。教程入口本轮出现 404/无法取得页面，首轮使用已核对的产品入口。

下面给出每渠道的零起步步骤及 A/B/C 的执行清单。Seka 稿件是待复核的原创草稿；中文用于用户审阅，实际发布语言按既有受众与偏好决定，不因模板语言固定为中文。各方案的六个选题构成连续六次独立执行的素材库，不要求同一周全部发布。


## 1. Facebook

运营目标：有管理权限的品牌 Page。

总频次：首月每周共 3 篇，A/B/C 各一篇；隔周轮换星期与时段；不另加广告帖。

转化路径：Page 原生帖子中的产品链接 → 对应场景入口 → 试用/注册；按钮入口单独归因。

账号筹备：

1. 核对 Page 管理权、地区、语言与现有帖子，保留原有品牌定位。
2. 从业务档案起草简介：服务谁、解决什么、一个可验证的价值点；准备封面和头像。
3. 整理入门、场景、FAQ 三个栏目，各准备两篇草稿；不借用客户身份。
4. 规划 Page 行动按钮到产品入口的路径；资料编辑与按钮配置须由对应能力完成验证。
5. 记录 Page、格式、目标网页及回传状态，先以一条已核准格式验证发布与访问。

实际能力边界：

- 当前仅管理 Page，群组发帖、私信和个人主页拓客不在已验证能力内。
- 主页装修、评论回复和原生 Insights 读取属于待补能力，不能把草稿计作完成。

官方参考：[参考 1](https://www.facebook.com/legal/terms)

### A. 问题解决专栏

方案编号：`facebook.problem_guide`。适用人群：已感到痛点、尚不知道产品的人。

待验证假设：先给完整解决步骤，再说明产品承担哪一步，能够吸引有实际需求的访问。

Agent 素材任务：纯文字可启动；有图片时制作一张三步骤清单，不要求用户拍摄。

逐次执行步骤：

1. 从已确认的业务和官网列出六个具体任务，按入门难度排序。
2. 每篇只解决一个问题，写清前提、三步操作、结果检查。
3. 结尾说明品牌关系，用同一行动语引导读者试做该任务。
4. 发布后核对真实回执与归因；将被证实的新问题加入下一批草稿。

Seka 首批六个具体选题：

1. 翻译 EPUB 前先检查哪四件事
2. 长文中人物名称不一致，先整理术语
3. 怎样从一个短样本开始验证翻译设置
4. 术语表和风格预设分别解决什么问题
5. 上传前怎样检查自己的文件
6. 翻译结果先核对哪些段落

第一篇草稿或分镜：

> 翻译长文前，先把重复出现的人名、地名和固定表达列成清单。明确哪些词需要保持统一，再检查风格是否符合阅读目的。Seka 的 Translate 提供术语和风格设置。先用你有权处理的小样本核对流程，再决定是否继续。

固定行动语：进入 Translate，检查自己的翻译设置。产品承接页：[查看入口](https://seka.one/translate)。平台只能使用主页入口时按渠道说明执行。

首轮只改这一点：同一个任务比较问题式开头和直接给步骤的开头；步骤与入口保持一致。

复盘后的具体动作：有访问少注册时核对入口是否延续原任务；无访问先改首句和场景，不增加发布量。

### B. 场景演示与过程证据

方案编号：`facebook.workflow_demo`。适用人群：知道问题、想确认产品是否适用的人。

待验证假设：展示真实输入和可核验的操作结果，比笼统宣传更能带来试用。

Agent 素材任务：Agent 准备三格过程图或 30–60 秒演示脚本；只使用真实页面与可公开示例，成片进入素材库后才发布。

逐次执行步骤：

1. 选择一个可公开、低敏的演示任务并记录来源。
2. 实际跑通准备、操作、结果；无法跑通的功能不演示。
3. 制作开始状态、关键动作、结果检查三段内容。
4. 配文注明演示条件与限制，链接指向相同任务的入口。

Seka 首批六个具体选题：

1. 从自写短文到翻译配置的完整演示
2. 同一段落怎样检查术语设置
3. 风格预设在哪里选择
4. 自动提取术语后为什么还要检查
5. 上传后先核对什么信息
6. 翻译完成后怎样人工检查

第一篇草稿或分镜：

> 分镜：①展示自写短文与术语清单；②进入真实 Translate 页面选择目标语言；③展示术语和风格设置；④说明报价以配置流程为准。只有真正完成的步骤才展示结果，未执行翻译时止于配置演示。

固定行动语：复现同一个小样本配置过程。产品承接页：[查看入口](https://seka.one/translate)。平台只能使用主页入口时按渠道说明执行。

首轮只改这一点：在同一任务中比较结果先展示与过程先展示；不改变演示数据。

复盘后的具体动作：观看多但访问少时把行动语与演示任务对齐；没有观看数据时不推断完播率。

### C. 决策疑问与入门承接

方案编号：`facebook.decision_faq`。适用人群：已了解产品、因顾虑而未开始的人。

待验证假设：直接解释输入要求、限制和上手成本，可以减少注册前犹豫。

Agent 素材任务：官网与业务档案中的事实卡；未知价格、隐私承诺、支持范围先留空。

逐次执行步骤：

1. 选取六个会阻止开始的问题，逐一核对业务依据。
2. 用结论、适用条件、具体下一步三段回答。
3. 把暂不支持的情况写明，不用夸张保证替代事实。
4. 依据真实注册与有效访问复盘，不以评论数量推定成交。

Seka 首批六个具体选题：

1. 我需要先准备什么文件
2. 翻译前如何确认 Credits 报价
3. 术语提取是不是最终术语表
4. 长文翻译结果为什么还需要复核
5. Translate 和 Collab Projects 怎么选
6. 没有确定目标语言时先做什么

第一篇草稿或分镜：

> 开始之前先明确目标语言、文件和结果检查方式。Seka 的具体 Credits 报价在翻译配置中确认；不要根据帖子里的估计直接决定预算。准备好后，再进入 Translate 查看当前可用选项。

固定行动语：先查看当前配置与报价。产品承接页：[查看入口](https://seka.one/translate)。平台只能使用主页入口时按渠道说明执行。

首轮只改这一点：比较先回答顾虑和先介绍功能；其余事实与入口一致。

复盘后的具体动作：把带来有效访问但不注册的问题对应到落地页承诺与实际步骤，修正断点。

## 2. Instagram

运营目标：当前账号自有主页。

总频次：每周共 3 篇，三套方案各一篇；不把没有素材的名额用重复图补满。

转化路径：图文/短视频 → 主页可用链接 → 对应任务入口；共享主页链接不能据发帖时间硬分到某篇。

账号筹备：

1. 确认主页身份、地区与受众语言，盘点自有可用素材。
2. 起草一句人群定位、一个结果描述和一个行动语；简介链接需实际检查可用性。
3. 建立统一字体、配色与封面编号，准备 6 张信息图和 3 个短视频分镜。
4. 把三类内容对应到同一真实业务入口；主页共享链接只作渠道归因。
5. 首发前校验图片和视频格式、商业/AI 声明与自有目标授权。

实际能力边界：

- 不预设普通配文链接可点击；优先核对当前账号的主页入口。
- 目前没有 Stories、自动私信、评论回复或主页编辑的已验证执行路径。

固定行动语：检查适合自己的路径与条件。产品承接页：[查看入口](https://seka.one/)。平台只能使用主页入口时按渠道说明执行。

首轮只改这一点：比较顾虑解答与更新说明，不把发布次数当作增长。

复盘后的具体动作：若更新没有匹配受众则降低频率；注册后使用情况未知时不称为激活成功。

## 已接入与后续验收

30 套通用方案与 30 套 Seka 实例采用同一版本目录。自主规划器只给已有合格目标加载本渠道的一个候选方案，并保存方案编号、目标事件、观察窗口、选择状态和当时证据。复盘从已确认发布、独立内容链接、站内会话和服务端事件联结；数据不足时不输出赢家。新接口可读取完整底稿与各目标反馈：`GET /api/agents/{aid}/operating-playbooks`。

现有 Telegram 和本地测试渠道不加载此目录，不因此修改 Telegram 的计划或状态。此接口是只读的，不连接账号、不扩大权限、不启用渠道、不创建付费任务。历史已有帖子没有方案标签时不能补猜标签，新方案样本从后续确认发布开始。

本地素材制作、版本与暂停保护、各渠道独立排期、周复盘已实现，详见 [素材与自主运营闭环](CREATIVE_AUTONOMY.md)。下一步外部验收包括：账号资料写入与置顶、各平台实际可点击入口、原生数据接入、逐平台许可/格式/回执校准，以及业务网站的真实转化部署。排期由结构化 schedule 执行，模型的文字建议不能突破间隔与滚动七天上限。本地检查不替代真实账号和真实转化效果。
