# 本地验收记录 · 2026-10-29

## 实测通过

- 当前完整自动测试 25 项通过。实际 PostgreSQL RLS、复合外键、消息/创建去重、授权卡版本及范围、暂停屏障、发布状态机、预算、统计来源和网址安全均有覆盖。
- 三个真正 Camoufox 进程同时读取公网 `https://seka.one`，数据库记录的三个执行区间实际重叠；一个 Agent 暂停后，其余环境仍能读取。时间证据：`.state/concurrency-verification.json`。
- 三环境本地发布同时执行；Cookie / LocalStorage / 设备配置隔离；浏览器进程重启后存储、UA、屏幕、平台、Canvas 像素与音频采样保持。空闲环境会被回收，让第四个 Agent 复用容量。
- 研究进程重启后，从持久化步骤恢复最后公网位置并重新观察，不复用旧元素句柄。
- 使用已配置的 DeepSeek，通过产品 API → Temporal → 原生工具调用 → Camoufox 访问真实 Seka，展开 FAQ，读取 Credits 计价说明，保存可查看的来源与截图。大写 Https 和后续无网址请求都覆盖。`.state/public-browser-verification.json`。
- 模型/调度/偏好保存/自主规划/实际浏览器本地发布的完整调用链通过。该脚本会归档测试业务，本地发布不计获客。`.state/runtime-verification.json`。
- 每环境独立受控转发，真实浏览器配置的上游代理不可用时导航失败，已转发连接/字节数为零；不回退直连。未认证代理、私网和其他 Agent 本地路径均拒绝。
- 三环境实际浏览器分别向 ipify、Cloudflare 测量出口，两探针结果一致；WebRTC 禁用。没有固定代理的测试环境全部保持独立出口未验证。`.state/environment-verification.json`。
- Telegram DOM 合约测试：现代多账号槽位识别、账号 2 不跳回账号 1、频道身份复核、真实输入和点击、提交后确认丢失再核对，最终只有一条内容、一个 attempt。此测试使用本地页面结构，**不构成 Telegram 实号验收**。
- 前端类型检查与生产构建通过。模型密钥只在服务端读取，不进入前端、对话或浏览器工具参数。

## 当前未通过 / 未实现

- Telegram 自有测试频道的真实登录、目标核对、明确授权、一次真实发布与服务器消息 ID 核对尚未完成。必须由用户在 lead 专属浏览器登录并提供自有目标；不得以 DOM 合约测试或本地测试站替代。
- 未配置各 Agent 各自的固定上游及预期公网 IP；不能声明独立出口通过。系统级强制出口、全面泄漏及地区一致性验收尚未完成。
- 其他十个平台发布适配、图片/视频上传、完整运营策略实验未实现。
- 公网网站回传和服务端转化未实号验收，当前转化为空；有效访问规则仍属于客户端观察。
- 原计划生产部署、备份恢复演练、多人身份/租户接入、长期稳定性压测仍待完成。

SDK 会提示代理宜配置地理位置匹配；这不等于观测到泄漏，也不能忽略地区一致性尚未验证。当前部署仍是本地所有者模式。

不得把“本地运行”“25 项测试通过”或“有 11 个登录入口”表述为完整产品已经验收。逐项状态见 `ACCEPTANCE.md`。
