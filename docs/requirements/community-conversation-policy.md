# 社群对话与产品入口

用户已确认在所有 Lead agent 的外部社群参与流程中，默认关闭普通讨论群主动推广，分别判断回复、介绍产品和附链接。需求基线 c801390，分支 codex/community-conversation-policy。已有群规、账号委托、去重和回执继续约束每次发送。

验收覆盖普通讨论群开题、受邀答疑、明确索要入口、允许自荐的广告位、无依据和旧待发稿。历史回放使用脱敏的动作类别及链接计数。真实机会审核应连续取样，包含跳过项，由审核人先独立判定后对照 agent 记录。30 项至少 27 项一致，越权、隐瞒利益关系或无依据链接为零。仅在当前账号许可内使用；有效接话率以可完整观察的已回复线程为分母，单列负反馈、平台限制和缺失观察。发布须核对设备定制并确认精确生产提交。

线上 16 条已确认的旧发送意图经新发送前检查回放：6 条讨论群开题拦截，3 条广告稿缺少新规要求的广告位许可依据而拦截，7 条无链接回复通过结构检查。此项不代替逐条文案评审。未修改历史消息。

在 agent 的 community_growth 配置启用 review_replies_only 可仅保存候选回复与跳过原因；仍按已有委托观察及管理成员身份。审核模式不会创建回复短链或提交消息。新决策的 result.decision 保存 policy_version、reply_to_mid、promote、include_link 和 review_only，result.outcome 保存最终处理。按 agent、账号、创建时间顺序取首 30 个已入群且有本版决策的任务，使用原消息编号在授权群内核对，不导出成员正文。

实际回访时，只有识别到原生回复关系、关联同账号同群已确认发送回执才在原任务 result.conversation_feedback 保存实质追问、礼貌回应或明确拒绝的消息编号；类别来自模型判断，可回查。客户端缺少关系或未覆盖观察窗时保留未知。单个被观测到的反馈不能证明观察窗完整。识别不了的语种或带条件的广告位许可保守跳过，产品问题可继续无链接答复。
