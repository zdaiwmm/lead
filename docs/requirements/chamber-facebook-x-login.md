# Chamber 的 Facebook 和 X 登录

家庭生产版本 d7b8c96 将 Chamber 的 Facebook 和 X 登录送入 Telegram 执行器。两个渠道均未绑定账号。用户选择复用该项目已验证的东京固定 IPv4，并让每个账号各自保存浏览器资料。普通执行器无法在本地绑定项目原 IPv6。通过家庭节点现有私有通道访问 Facebook 和 X 的官方登录网址，两个 HTTPS 请求均返回 200。

## 启用与验收

在家庭 API 和普通浏览器服务的环境中，将 Chamber 的项目 UUID 加入 `LEAD_SPLIT_FACEBOOK_X_LOGIN_AGENT_IDS`。在同一个发布窗口启用这两处配置。普通浏览器复用该项目现有的 `LEAD_REDDIT_IPV4_<项目 UUID 去连字符后大写>` 配置、私有隧道与出口身份记录。该分流默认关闭，适用于明确选择共用此出口的项目。

打开账号时按项目、渠道和账号分配资料，待连接账号重试复用已有资料。人工接管按有效会话取图和输入。X 核验账号后，其主页检查也使用同一份资料。已有绑定若仍使用默认资料，先核对其历史登录环境。停用前先结束两个渠道的接管，保留已绑定的资料和出口记录。

在独立 PostgreSQL 与原生 Camoufox 中，用模拟站点核对首次失败和重试、登录网址、JPEG 首帧、输入、账号核验、结束和重开、跨项目及过期接管拒绝、Telegram 会话隔离。验证固定出口复用与丢失配置时停止连接。合入与发布后，分别从生产工作台核验两个真实登录表单，账号凭据由所有者输入。

任务分支为 codex/chamber-facebook-x-login，起始提交为 40ec5d453553e0e590861d0e12a007281efe5fd2。家庭生产发布按仓库流程确认具体提交及环境。
