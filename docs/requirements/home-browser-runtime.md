# Chamber 的 Reddit 登录使用独立东京 IPv4

家庭生产版本 f1385b6 已把 Reddit 分配到独立资料，普通执行器缺少可写运行目录。家庭节点临时服务用同一引擎启用了专属 HOME/TMPDIR，验证了网络隔离与公网双探针。先前 IPv6 方案无法解析 www.reddit.com 的公网 AAAA 记录。东京固定 IPv4 的原生浏览器验证中，首页返回 403，官方 /login/ 入口显示用户名与密码框。用户确认 Reddit 单独使用已核准的东京 IPv4，Telegram 继续使用原 IPv6，修好后上线并验证登录画面。

普通服务为该项目配置 LEAD_REDDIT_IPV4_ 加去横线的大写项目 UUID。独立 Reddit 资料第一次启动时，在项目锁内绑定该渠道专用的网络身份；同项目的 Reddit 资料可复用该身份，原默认资料继续持有原网络身份。项目的地区、时区与语言要求及生产出口双探针继续生效，双探针按资料对应的预期地址核对。已绑定出口配置缺失或更换时停止连接。运营总览显示默认环境的出口。

家庭节点与东京节点的受审阅配置位于 infra/home-reddit-login。东京使用专用无会话 SSH 账号与独立出站规则，仅允许公开 IPv4 HTTPS。只有规则装载成功才发布其公钥授权。家庭节点生成仅用于该通道的密钥，复用既有东京 SSH 传输入口并校验相同主机指纹。SSH 动态转发仅监听服务专有目录中的 Unix 套接字，浏览器服务只读挂载该目录以支持隧道重连。HOME 与临时文件进入普通服务私有运行目录。Telegram 的资料、进程和网络入口保持原配置。

部署前后须核对东京静态地址仍属于既定实例，校验节点配置与主线提交字节、有效 sshd 和出口规则、浏览器生产进程版本、固定 IP 双探针及真实登录表单。界面验收停在用户可输入凭据的位置。回退先停止新入口并撤销其专用公钥，保留账号资料及已经记录的网络身份；恢复原应用前须还原本次增加的资料出口关联，不影响 Telegram 的默认网络身份。

### 私有 SSH 入口的安装与回读

家庭节点的回环端口 19190 通过现有传输连接东京 127.0.0.1:19189。该私有 sshd 使用独立配置 /etc/lead-tg-stcp/sshd_config。将已审阅的 tokyo-sshd.conf 保存为 /etc/lead-reddit-link/reddit-user.conf，将 private-listener.conf 追加到私有配置末尾。新增准入只匹配 Reddit 专用系统账号，不扩大全局 AllowUsers 列表。公共 SSH 服务无需加载此账号的配置。

安装前备份并核对私有监听地址、主机指纹、现有 Telegram 账号及其唯一 PermitOpen。用候选配置运行 sshd -t，并对 Telegram 账号与无关账号分别运行 sshd -T -C，与改动前逐字节比对。对 Reddit 账号核对唯一准入、专用公钥文件、仅本地 TCP 转发、仅 443 端口、禁用会话与 Unix 转发。验证通过后原子替换配置，仅向该监听服务的主进程发送 HUP。回退使用同样的核验和重载方法。既有 Telegram 转发进程及 IPv6 出口需独立回读。

本修正只补充节点安装配置。家庭生产应用仍使用已确认的 900e6a9584b589672f7d7af129f8de98ec18f6f3，应用镜像与该版本的发布单继续按原程序验收。
