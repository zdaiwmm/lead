# 通用执行框架与独立渠道交付

## 范围与验收

用户已确认统一公共执行能力、代码来源与发布管理，保持 Telegram / Reddit 独立账号、Profile、出口、队列、额度、重试与进程恢复；本次授权包含实施、提交、正常 PR 合并和现有 home-production 发布，以及两个渠道真实执行链路验收。

验收：换号无需改执行器代码；单渠道失败不拖停另一渠道；发布逐一核对实际执行器加载的公共模块和平台适配器，不能只核对主应用 selector。保留所有未知发送记录，只查原回执。既有授权与经营策略不因迁移扩大。

方案：公共能力来自同一精确主线产物；渠道独立绑定自己的不可变版本和进程。设备特有平台行为作为受控私有适配器交付，公开仓库仅保存通用接口、校验与迁移机制，不包含私有设备源码、账号或业务资料。每个执行器的版本清单包含公共版本、适配器摘要、实际进程及启动回执；应用与渠道交付分别记账，可以独立重启、核验和回退。

## 验证与交付边界

- 共享浏览器接口保留 HTTP 请求格式，通过内部回调显式选择平台步骤与回执重载。任务局部 Profile 作用域覆盖发现、人工检查和关闭路径；发现与计时只读取自身账号的检查点。换号后新建正确绑定的任务，不改写或重派旧记录。
- 私有迁移验证公共模块未被替换；未知/已提交动作只查原回执；现网本地模型限制保留。设备业务策略按原 active 摘要冻结进适配器清单，原受限子进程包装不变，旧解释器及公共模块覆盖移除。后续私有策略变更必须重新生成并验证适配器清单。
- 公开镜像显式包含浏览器隔离、研究、备份及迁移运行依赖；外置只读环境文件通过 `LEAD_ENV_FILE` 配置。镜像不包含本地凭据或私有适配器。
- 本地隔离数据库验证范围包括任务归属、换号、未知发送、健康门禁、共享回调、运行配置、发布证明及回退。原生浏览器丢失回执用例已通过；实际 Linux 私有业务隔离和线上双渠道链路仍由部署后的独立验收负责。
- 只读盘点：Telegram 账号连接且既有策略运行；Reddit 账号连接，平台发布许可仍 pending，现有渠道任务明确等待 `source_permission_required`。本需求不把该许可改为批准，不为验收发送额外社媒内容。
