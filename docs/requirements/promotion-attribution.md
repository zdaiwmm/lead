# 推广访问归因实施方案

## 业务规则

工作台「获客效果」默认展示当前 Agent 推广带来的流量。推广点击只来自通过现有过滤的短链跳转。到站 PV、访客和有效访问按本次访问的推广入口统计。网站像素仍记录直接访问，用户能在「全站流量」或「未归因」查看。全站 UV 以匿名设备独立去重，同一设备可同时出现在多个渠道。

同一标签页内，有效推广入口开启一次推广访问。同源页面导航、刷新和 SPA 路由在会话有效期内沿用该来源。无推广参数的新外部入口、地址栏直访、超时后活动开启新会话。独立标签页各自管理访问，匿名设备标识沿用。缺少同源导航证据的新文档采用未归因。服务端继续验证短链签名、网站、Agent、有效期，兼容现有经过校验的旧推广码。测试环境单独统计。

注册、线索与订单沿用现有最近有效触点及该触点冻结的归因窗口。直接回访可以产生一笔有证据的延迟转化，但回访本身计入未归因流量。服务端转化按业务去重和可信级别统计。

## 实施与历史数据

1. SDK 按标签页和访问入口隔离会话与推广凭证，保留重试队列中事件发生时的证据。旧 SDK 的缓存不导入新会话。
2. 服务端入库先验证点击有效期。浏览流量按访问会话确定来源，转化按已验证触点或点击确定来源。推广视图、趋势、渠道、地区、人数、金额使用同一个筛选条件。全站明细继续可查。
3. 报表 worker 用已有的按日队列和事务，从源回执重建旧版日汇总、小时汇总和去重集合。旧 SDK 曾缓存并重复上报推广来源。历史回执能区分本次会话与过往转化触点时，按本次会话重算。旧会话保存了推广码而缺少当次导航证据时，无法区分真正的推广落地和旧缓存重放，保留其原会话来源。旧快照在推广数字重算期间显示待汇总。原始回执、订单和匿名身份保留。
4. 在隔离 PostgreSQL 与 SDK 测试中核对下表，再构建工作台。在 GitHub 推送完整候选提交，通过该提交的 CI 后准备家庭节点的发布包。

| 验收场景 | 推广统计 | 全站统计 |
| --- | --- | --- |
| 新设备首次访问裸网址 | 点击 0，PV 0，设备 0 | PV 1，设备 1 |
| 该设备随后从短链进入，站内再浏览一页 | 点击 1，PV 2，设备 1 | 累计 PV 3，设备 1 |
| 同标签页或新标签页再次从地址栏进入 | 推广 PV 与设备数不增加 | PV 增加 |
| 直接回访完成注册或支付 | 按有效触点、冻结窗口和业务去重核算转化 | 业务事件照常记录 |
| 无触点、失效凭证、其他 Agent 或测试会话 | 排除对应推广成绩 | 按原有校验规则接收或拒绝 |
| 旧汇总、重复任务、进程中断 | 重算完成后显示同一结果 | 已接收的事实可重新核对 |

## 发布、核验与回退

生产目标是家庭 PC 的采集器、统计消费者、API 和工作台。核对当前挂载与版本，使用同次 CI 制品，保留旧挂载。先切统计消费者、采集与查询服务，再切页面；发布过程中留意队列和像素脚本 300 秒缓存。以合成环境验证互动链路，线上只读对照同一 Agent、同一北京时间范围内的推广、全站与未归因分组。独立验证全站浏览量等于所有渠道浏览量之和，推广设备数按所选渠道并集去重。记录版本、构建号和汇总队列状态。若出现全站数据缺失或渠道对账失败，恢复此前挂载和程序，按此前版本重算受影响的日期。

### 家庭 PC 操作

在任务分支从已推送且 CI 通过的完整提交生成安装目录。

```sh
python3 infra/chamber_pc/prepare_release.py HEAD --workspace
```

进入命令输出的目录，执行 `python3 activate.py --attribution`，在 PC 的 SSH 终端完成管理员认证。安装器检查当前工作台 BUILD_ID 和各进程实际挂载的文件摘要，使用独立的 systemd 配置切换四个服务，检查服务健康、文件摘要、工作台版本，并用只读查询对照当天推广与全站 PV、设备数。服务异常或对账超时会还原挂载。手动回退使用同一目录下的 `python3 activate.py --attribution rollback`，通过「数据状态 → 重新汇总」选取受影响的日期。成功激活后检查 30 天趋势、未归因筛选及汇总队列，待旧日期重建完成后验收历史报表。


## 本地验收记录

开发基线为 Chamber 分支 `743d54f`，任务分支为 `fix/promotion-attribution`。在隔离的 PostgreSQL 18、Temporal 和项目工作台构建中完成以下验证。

- 79 项相关回归通过，覆盖像素、获客、服务端转化、旧快照重建、真实异步消费者和发布准备。
- 同一设备经过首次直访、短链落地、站内浏览、直接回访。在数据库回执和对外接口中，短链点击 1，推广 PV 2，全站 PV 4。推广确认金额 8 CNY，全站金额 20 CNY，重复支付只计一次。
- Chrome 验证真实同源链接导航、刷新、新标签和同标签裸网址回访。另一组隔离样本在工作台的推广、全站、未归因筛选下分别显示 PV 1、3、2；卡片与明细一致。TypeScript 与 Next.js 生产构建通过。
