# 多渠道持续执行与模拟验收

用户确认先实现、隔离模拟、通过后上线，绑定真实账号后再做灰度业务验收。基线为 fe3716c，首批并发及首访提交为 6a5686c。后端先在默认关闭的项目试点中复用已有渠道目标核验、发布计划、动作账本与回执。验收包括动态启停、过期代数、独立持久计时、授权缺失、原意图核对、模拟新客和已有路线兼容。真实发布仍按仓库规定核对目标环境与精确 SHA。

## 已实施与已验证

渠道时钟按启用的目录项和控制版本持久登记。每种渠道在独立 Temporal 工作流中按目标期限轮转，等待不占执行槽。已有增长实验继续由实验内核负责，其他已迁移的发布只由渠道时钟选择。最终产物提交与网页点击前再次核对时钟代数。复用已有选题、平台许可、目标资格、素材校验、发布任务、唯一分发码及首次归因；时钟可把与目标、产品版本匹配的已核验机会传给内容决策，研究证据本身不授予发帖权限。

已在单独创建的 PostgreSQL 数据库、原生 Camoufox 和离线 Facebook/Reddit 页面复现从模拟机会报告到客户首购的路径：读取经核验的样例需求、确定目标、生成内容、保存发布计划、点击、回读和首访归因。平台和模型使用固定替身，账号、站点及交易为测试样本。Facebook 已接收帖子后故意丢失返回，原动作进入未知，再次执行只回查，两个平台各留下一个帖子。模拟访客先走 Reddit 链接再走 Facebook 链接，在后者完成购买，重复回调后项目一人且归 Reddit。独立测试与历史回归合计 54 项通过。


## 账号环境与发布边界

迁移 0027 保留旧项目的默认 Profile 和已绑定账号的原登录。试点项目新绑定的目录渠道按账号使用独立持久配置，网关以环境 ID 保存 Actor、租约、锁、代理桥、设备文件和浏览器会话；项目级资源池仍限制同时开机数。账号环境可共用项目已核验的出口，核对设备和账号时仍需匹配当前 Profile。浏览器操作按目标绑定到账号；人工接管按会话 ID 路由和结束。旧单环境保持原有暂停语义。独立环境的最终点击用项目共享提交门闩，项目暂停仍具排他性。显式新增同平台绑定可在 connect 请求使用 new_account 并沿用返回的 account_id。

备份时对整个项目取得文件独占锁。加密归档包含默认环境与各独立账号经过校验的身份和登录文件，恢复隔离区按账号目录、文件摘要和数据库身份对账，再允许切换节点。原默认配置继续兼容。隔离验收已用两个实际浏览器进程验证跨账号 cookie 不可见、分别提交、关闭一个不释放另一个的租约；完整备份解密后仍能核对两份账号环境。

## 发现、分发及持续运行

研究和投放分开计时，沿用项目的模型设置、预算准入、主机压力检查和来源核验。研究读取搜索页中实际出现的链接，核对原页面及可引用的规则，先保存浏览证据，下一次活动才评估。没有渠道数据接入许可、没有符合条件的目标、已使用同一份需求证据、额度不足或页面受阻时，记录原因与复查时间。试点的 Reddit 和 Facebook 只在最新核验为可分享、来源与已授权目标一致时策划外发。搜索结果和注册／付款在账本里是不同事实。实验内核与 Telegram 原生社群／主动咨询流程沿用原负责人。

配置沿用 LEAD_CHANNEL_ATOM_AGENT_IDS 项目白名单。运营方仅将已经取得适用商业来源访问许可的渠道写入 LEAD_APPROVED_DISCOVERY_CHANNELS。平台写入仍受平台能力、单账号登录及目标动作授权约束。授权和真实账号到位后才能对相应平台做线上验证。

迁移 0028 将原分发来源绑定到 tracking_links。人工链接、帖子、Telegram 群参与和入站会话回复共用建链入口。项目、渠道、分发意图和位置确定同一登记，同一请求并发重试复用同一码；变更已登记目的地址必须提供新版本。旧链接保留原状。支持 Discord 来源短码，实际向 Discord 写入仍取决于专用适配器和平台许可。

双渠道浏览器用例已去除预置成功报告，从产品描述开始运行公开需求检索、实际渲染原文、保存引文、验证分享规则、生成并投放带码内容、处理响应丢失，到测试业务后端回传首购，覆盖渠道归属与项目去重。平台页面、模型决策、用户及交易为合成数据。在真实 Temporal 测试服务中通过了加速时间超过 24 小时的两条时钟，活跃通道执行 103 轮并跨越一次工作流续跑，长等待通道运行 3 轮，两段执行历史均可重放。加速测试未测量生产机器连续运行一天的容量或获客效果，实际 24 小时观测属于上线后小流量验收。

## 家中生产节点的首次迁移与回退

普通应用镜像不含迁移工具。首次切换须在本次完整 main SHA、home-production 和迁移维护窗口获批后，由节点管理员安装该版本单独审阅的 home_systemd_release.py、home_live_maintenance.py 两个受信工具。保留原工具、可启动的旧镜像和可恢复的数据库备份。应用工人和真实账号均无数据库结构修改权限。

1. 先使用节点的 current、verify 核对各服务正在运行的 SHA、节点代码定制和独立监控。停接新任务，排空在途提交与未知回执，确认站点可恢复备份。试点项目名单与来源许可名单初始为空。只读实测家中数据库的原版本为 0026_local_restore_proof；普通主线环境的原版本为 0025_site_devices。节点恢复证明使用已入 Git 的同名原迁移 5a31153，0029_merge_channel_restore 汇合两条历史，保留原函数、权限及记录。检查实际版本不符时按真实迁移差异单独评估。
2. 节点数据库管理员在专属 Lead 数据库和受信任的已核对 Git checkout 内，使用现有受限运行环境加载已配置的 LEAD_STATE_DIR，先在备份副本上演练。已有生产库采用现有迁移入口 PYTHONPATH=services/api python -c 'from lead_app.migrations import upgrade; upgrade(roles=False)'，保留线上授权和平台能力表；独立空环境按原 scripts/migrate.py 初始化。0026 为历史回调用空来源，0027 把原环境标为 default，0028 为旧链接保留原始映射。恢复前核对旧 URL、现有登录目录及历史事件数。数据库迁移在应用切换的表锁建立前完成。
3. 运行管理员已安装的 home_live_maintenance.py channel-schema；以节点身份独立核实当前结构、唯一键、分发保护和单环境回退条件。发布钩子只认可已评审的这六个文件的精确 Git 内容（含示例配置），核验不通过不切换。继续使用原有精确 SHA 发布、维护锁、备份、绑定、独立回读与恢复入口。
4. 先验证默认关闭的既有路线。开试点前另存项目和账号环境备份，确认产品域名能接受签名到站、业务后端能发送已验证的首次事件。启用后若需回切，先暂停相应渠道并排空或隔离未知动作。首次产生独立账号环境后，旧版单环境应用不能直接接管这些账号；应维持新版关闭试点、修复前滚，或按节点恢复流程对账和恢复，不应删账号或事实表。

试点绑号有一个明确的「绑定并启动获客」按钮，同时授权在账号确有管理权、平台许可且可分享的目标发布文字和一次连接验证帖。由系统跟随已核实的原文，匹配登录身份和管理入口，建立仅文字的目标授权并按原流程回读验证帖。没有这份托管授权的旧账号保留原目标授权卡。真实平台账号或应用仅有阅读权限时只做研究。正式内容和连接验证分别入账，连接验证不计新客。

强制两个实际浏览器都到达点击前的同步点，验证了允许的账号写入可以重叠。沿用租户并发 Agent 上限，同项目不同独立环境可同时提交；同环境的写入依旧互斥。计时活动同样检查工作时间、故障退避与项目状态。回执入账放在独立执行线程，避免等待另一账号的数据库提交时阻塞浏览器事件循环。
