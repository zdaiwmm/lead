# 网站像素与事件接入

本地产品已接入分步安装、真实事件测试、标准／自定义事件管理和事件明细。公开网站需要部署方配置公开 HTTPS 的 LEAD_PUBLIC_URL；本机地址无法接收外部网站的回传。

## 用户流程

未接入时，获客效果只显示嵌入代码、安装检测、事件测试三步进度。复制代码不表示安装完成。安装检测每 2.5 秒检查真实网站回执，收到新鲜 PageView 后直接切换到事件设置与测试弹窗，不经过主页面再次点击。

同一网站只需获取并安装一次代码。再次打开会直接显示已保存网站及原连接的固定代码，可复制复用；只有更换网站地址时才需要保存。读取设置、刷新、检测和修改事件不会更换安装码。旧版已安装的时效凭据在原有效期内仍兼容；更换站点连接、采集地址或部署签名密钥时需核对对应安装代码。

本地非生产环境支持 `http://127.0.0.1:8787`、`localhost` 及 IPv6 环回测试网站，包含自定义端口。登记网站不发起网页读取；该例外只作用于像素接入，不放宽公开网页研究和推广链接的地址限制。Origin 精确校验、连接状态与 Agent/工作室权限继续生效，生产环境仍要求公开网站。

事件设置管理标准／自定义事件与固定业务埋点。埋点按业务成功回调接入一次，开始、重复或结束测试均不修改业务代码。网站级“完整流程测试”独立展示实时事件列表，持续接收同一会话内所有已配置事件；不会收到一个事件后就停止。至少一个当前版本业务事件有真实测试回执后可以完成接入，也可以先接入访问。

接入后显示独立访客、访问会话和事件汇总。点击事件查看各事件的次数、人数、最近发生和接入状态。没有数据保持未知，不把测试记录或演示数当作正式数据。

## 采集与身份

- 安装代码绑定一个 Agent 的网站连接。公开浏览器写入码只允许指定网站 Origin 和页面 URL，不具有服务端回传权限。
- SDK 自动上报 PageView、单页应用路由变化和满足配置时间的前台活跃事件。重载同一连接的 SDK 不重复初始化。
- 匿名访客编号为本站存储的随机 UUID，不采集设备指纹，不扫描表单。UV 按匿名编号去重；访问会话按 30 分钟无活动切分。清理存储或不同设备会产生不同匿名访客，不能将 UV 称为跨设备人数。
- 注册、登录后显式关联业务用户编号。编号在服务端按连接散列保存，用于同一业务用户的事件人数去重。退出账号时调用 reset，避免后续用户沿用先前身份。
- 旧版 pageview/engagement 上报和服务端 conversion 接口继续兼容。缺少匿名编号的旧记录不能推算独立访客或转化人数。

SDK 加载前的调用进入队列；异步调用会等待 SDK 和首次访问回执。事件编号必须稳定，业务失败不能通过重新生成编号绕过去重。

    await leadq('identify', String(user.id));
    await leadq('track', 'CompleteRegistration', {}, {
      event_id: 'signup:' + user.id
    });

    await leadq('track', 'Activation', {
      action: '首次成功导出报告',
      rule_version: 'activation-v2' // 使用事件设置中当前生成的规则版本
    }, { event_id: 'activation:v2:' + user.id });

    await leadq('track', 'ReportExported', { action: '报告导出成功' }, {
      event_id: 'export:' + report.id
    });

## 推广来源与异步支付

Agent 分享链接自动携带 lr；服务器核对当前连接、Agent 和目标网站，创建独立推广触点。站内跳转沿用本站上下文；同一会话从来源 A 再进入来源 B 会保留两个触点，不覆盖已保存到业务记录的来源。

无来源、无效来源或其他 Agent 的来源不会拒收当前网站的合法业务事件，而是保留为未归因。公开来源码不是服务端鉴权凭据。

注册或创建订单时等待来源解析，并将完整快照交给业务后端保存：

    const attribution = await leadq('attribution');
    await createOrder({ product_id: product.id, lead_attribution: attribution });

支付回调必须读取订单保存的快照，不读取当前浏览器的新来源。业务后端用独立密钥调用 POST /collect/server/events：

    const source = order.lead_attribution || {};
    await fetch(COLLECT_ORIGIN + '/collect/server/events', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': 'Bearer ' + SERVER_KEY
      },
      body: JSON.stringify({
        connection_id: CONNECTION_ID,
        event_name: 'Purchase',
        event_id: 'purchase:' + order.id,
        user_id: String(order.user_id),
        lead_attribution: source,
        occurred_at: order.paid_at,
        properties: {
          order_id: String(order.id),
          value: order.paid_amount,
          currency: order.currency
        }
      })
    });

来源为空可以省略匿名编号与触点，业务事件仍会保留。触点必须属于此连接，业务发生时间必须落在触点的归因窗口内；过期触点不再计为有效归因。跨域网站需显式传递业务快照并匹配各自的网站连接，不能依赖跨站浏览器存储共享。

## 去重与时间

事件编号在同一连接及测试／正式范围内唯一，重复内容幂等返回；同编号用于不同内容返回冲突。注册按业务用户、有效使用按用户与规则版本、支付按订单编号另做业务去重。事件次数与人数分别计算，业务事件汇总排除 PageView、Identify、Engagement 和测试数据。

保存 occurred_at 和 received_at 两个时间。业务明细按实际发生时间统计近 30 天，测试反馈显示接收时间。事件时间必须带时区，不能超过未来 5 分钟或早于近 30 天。服务端可信转化继续与公开浏览器观察分开；Agent 原有转化目标只使用带有效来源的服务端确认事件。

## 会话级完整流程测试

1. 安装一次固定代码，并按事件规范接入业务成功回调。后台开始测试只生成有效期 30 分钟的网站级测试链接，不生成需替换到网站里的测试代码。
2. 打开链接后，SDK 从 `lead_test` 自动读取测试会话，为测试创建独立的匿名访客、用户和访问会话。所有已配置事件使用同一个测试码上报；原正式访客身份与来源不会被测试覆盖。
3. 后台持续显示浏览、注册、加购、结账和服务端支付等已接收／去重／拒绝结果。测试开始时保存事件规则版本，后来变更或新添加的事件需开始新测试会话。标准事件也必须先配置，自定义事件需明确触发行为。
4. 下单时 `await leadq('attribution')` 返回完整快照，包含网站连接、访客、会话、触点和可选 `test_code`。网站后端将快照原样保存在订单，通过 `lead_attribution: order.lead_attribution` 回传。采集接口自动解析测试上下文，无需临时改支付回调。显式字段与快照冲突时拒收，其他网站的快照也拒收。
5. 后台“结束测试”（关闭活动测试弹窗也会结束）或网站 `await leadq('endTest')` 结束服务器测试会话。在线 SDK 每 3 秒及重新聚焦时核对状态，清理地址中的测试参数、测试身份、测试来源和缓存快照，恢复原正式访客。离线网站联网后核对清理。结束本身不自动发出正式 PageView。
6. 过期／无效测试停止上报，须重新打开有效测试链接或明确调用 `endTest` 退出后继续；网络失败不会自动降级成正式事件。已保存的测试订单永久保留其测试上下文，即使网页已结束测试，迟到的支付仍被拒收，不会变成正式转化。

`reset` 仅重置当前身份，测试中调用仍留在测试范围；结束测试使用 `endTest`。`await leadq('testStatus')` 可查询状态，SDK 通过 `lead:test-state` 事件通知页面。临时测试能力只能用于检查或结束本会话，仍需精确网站 Origin 和安装码，不具有工作室管理或服务端回传权限。

测试和正式事件使用独立去重范围，测试过的用户或订单不会阻止后续合法正式记录。测试记录、测试身份和测试访问不计入正式获客数据。配置变更后，原版本回执不算新版本通过。

回传密钥仅在生成时显示，保存在网站后端。更换密钥会撤销旧服务端密钥，不影响公开浏览器安装码。事件管理写入遵守工作室、Agent 范围及 analytics.manage 权限；只读报表不返回安装写入码或服务端密钥。

## 本地完整链路验收

测试页位于 `pixel-test/`。`python3 pixel-test/server.py` 在本机 `127.0.0.1:8787` 提供静态页面与仅允许测试范围的订单后端。验收连接及独立服务端密钥保存在忽略版本控制的 `.state/pixel-playground.json`（0600），浏览器只读取公开安装代码，不获得服务端密钥。订单保存于本机 SQLite，金额由测试后端按固定测试商品计算；所有交易均为模拟。

浏览器按固定安装 → 开始网站级会话 → 浏览／注册／加购／结账 → 服务端模拟支付 → 后台核对服务端 Purchase → 结束测试 → SDK 清理的顺序验收。没有有效测试上下文时，订单后端拒绝创建；不会向正式范围发送模拟支付。
