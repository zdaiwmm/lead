## 本轮补齐的工程内容

- 十个平台独立网页适配与 Telegram 媒体流程；真实文件选择、上传字节验证、图片/视频组合、标题和必要披露。
- 素材解码、图片隐私元数据清洗、视频安全容器重封装、容量/并发限制、跨 Agent 引用和内容篡改拦截。
- 统一持久准备与发布账本；上传后中断不重传，提交确认丢失不重复点击；作者和目标信息不能由正文中的链接冒充。
- 首次验证只能由完整内容一致的已接受授权卡、实际发布 ID/证据和已确认的尝试记录提升；按目标、格式、适配版本记录。
- 偏好与素材声明形成新配置版本，使旧方向排队内容失效；不会要求用户每日分配工作。
- 网页资料全文检索、所有者鉴权 SSE、独立服务端转化回传和持续集成。

本地软件收尾已增加环境/固定出口原子分配、故障隔离自动等待、身份/地区/系统边界实测状态、用户来源素材事实、详细计量、安装升级检查、所有者绑定、安全恢复安装与切换、导出和定向数据清除。混合运行器及自动判定器已补，预演通过受控场景。详见 [LOCAL_READINESS](LOCAL_READINESS.md)。

剩余验收是：完整 72 小时观察与资源判定，目标生产节点、真实 OIDC/异地对象存储/加密卷、实际固定独立出口与完整泄漏矩阵、完整规模异地灾备、各平台许可及全部实号验收、真实业务网站采集、单位成本与获客策略有效性。六个事实质量样本不替代效果评估。逐平台材料与明确不开放原因见 [CHANNEL_REVIEW](policies/CHANNEL_REVIEW.md)。

真实账号的密码、验证码、身份验证和扩大授权由用户在专属浏览器处理。测试业务会归档，测试发布不进入获客成果；不修改用户已有业务或登录资料。
