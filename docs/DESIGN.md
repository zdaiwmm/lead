# lead 视觉设计规范

## Overview

**版本：1.3，2026 年 10 月 30 日，代码已实施，桌面及320/390px窄屏弹窗已通过真实Chrome验收。** 本规范是 Agent 运营工作台及相关界面的正式视觉标准。用户确认的分区原型已应用到产品代码。[先前方案](design/lead-visual-system-v1/DESIGN-v1.0.md) 与 [旧版规范](design/lead-visual-system-v1/DESIGN-legacy.md) 归档供追溯。

本次修订统一编辑与详情入口：主工作台持续展示摘要，头像名称、偏好、更多设置、全部记录及渠道管理通过独立弹窗完成，保持主区布局与滚动位置稳定。模块边界、色彩职责、字体与功能范围延续上一版。

**Creative North Star: "自主运营清楚可见"**

lead 的核心体验是持续运营及其结果。用户打开页面，先确认 Agent 是否正常运行，再判断带来的有效访问；需要时编辑方向、连接账号或补充一句话。页面以信息秩序建立信任，以局部光影与温暖的操作色建立识别度。

设计情境：小团队负责人晚间在调暗的显示器上短暂检查自动运营，先看状态与结果，再决定是否干预。采用低色度石墨暗色；正文和数据区保持稳定、清晰的对比。此为设计情境，日间与系统浅色主题需另行验证。

本系统从 [Huly](https://huly.io/) 提炼局部光源与空间深度，从 [Raycast](https://www.raycast.com/) 提炼暖色与暗部的色彩张力，从 [Linear 的产品演示](https://linear.app/) 提炼对齐、文字层级和渐进操作。以下具体字号、色值、间距及组件规则均为 lead 的原创设计决策，来源观察见 [参考分析](design/lead-visual-system-v1/REFERENCE_ANALYSIS.md)。

### 信息优先级

| 层级 | 用户要知道什么 | 界面分配 |
| --- | --- | --- |
| 第一层 | 正常运营吗，带来了什么结果 | Agent 状态、获客数据和趋势，最大的连续内容区 |
| 第二层 | 正在为谁推广，以什么方式运营 | 业务与运营偏好，直接展示，弹窗编辑 |
| 第三层 | 接通了哪些平台，最近做了什么 | 轻量社媒栏、少量最新工作记录 |
| 第四层 | 用了多少资源，需要处理什么 | 用量与费用摘要、异常的就近处理入口 |
| 按需辅助 | 补充信息、调整方向、提出问题 | 右侧对话，不承担日常任务派发 |

### 布局与空间

- 桌面基准宽 1440px：导航 184px；扣除导航后的 1256px 按黄金分割，运营主区约 776px（61.8034%）、右侧对话约 480px（38.1966%）；主区画布左右边距各 40px，模块内部再保留 28–32px，形成清楚的内外层次。
- 主区独立自然滚动；对话保留自己的消息滚动区和底部输入框。不能为了在 900px 屏高里塞下所有内容而缩小正文或挤压模块。
- 首屏顺序为身份和运行状态、轻量社媒栏、获客效果；偏好、工作记录和高级摘要在主区顺序展开，持续可达，不藏入标签页。
- 组内间距 16–24px；面板内部 28–32px；独立面板之间保留 32–40px 完整露出的画布间隙；主要信息组之间 48–56px。用 4px 步进，允许文字光学校正 1–2px。
- 标题至内容 20–24px，标签至数值 6–8px，图标至文字 8px。所有模块主起点、操作末端、时间戳分别对齐。
- 社媒账号是紧凑的上下文面板；获客效果是最大、稍亮的完整主面板；业务与运营偏好是两个可独立编辑的次级面板，并列时露出至少 24px 画布；工作记录和高级摘要各占独立的全宽面板，依次下移并降低视觉权重。
- 面板高度由真实内容和内边距决定，不锁定一个高度再缩小字号塞入内容。面板间的间隙保持无标题、无分隔线、无装饰，形成真正的停顿。
- 每个面板的标题、动作和内容在同一边界内。不能让标题贴近上一模块、内容落入下一模块，或仅靠一条竖线划分两个独立配置区域。
- 1280–1439px：导航 176px，余下空间仍按 61.8034% : 38.1966% 分割，主区边距 32px。1100–1279px：导航收窄，对话按需展开，主区不压成窄列。768–1099px：主区为主，对话从专用入口展开。小于 768px：边距 20px，偏好与高级摘要纵排，社媒图标换行，保持所有平台可达；对话进入独立全高面板。

## Colors

YAML 中的 OKLCH 为规范色值。颜色名称表示用途，不能按个人喜好跨角色挪用。

| 令牌 | 职责 | 应用边界 |
| --- | --- | --- |
| canvas / surface / raised | 画布、内容、交互浮层 | 用细微明度差建立深度，不用大片蓝底代替层次 |
| module / module-primary | 独立模块、核心效果模块 | 配合完整细边界和画布间隙形成分区；核心模块略亮，辅助模块降低权重 |
| text / text-secondary / text-muted | 正文、次要内容、元信息 | 灰度变化承担大部分层级；元信息仍需可读 |
| action / action-hover | 关键操作、品牌识别 | 珊瑚色不用于每个链接、每个数字或每个分隔线 |
| data | 数据趋势与选中数据 | 紫罗兰趋势线，不代表错误或异常 |
| success | 正在运行、连接正常 | 小圆点结合文字；不用大面积绿色卡片 |
| warning / danger | 需要处理 / 操作失败 | 只在真实异常附近使用，不用珊瑚操作色表达失败 |
| focus | 键盘焦点 | 清晰的 2px 外圈，外偏移 2px |

**色彩职责规则。** 中性色为底，三种常用功能色分工：珊瑚用于操作，紫罗兰用于数据，薄荷用于状态。工作区高饱和色的可见面积以不超过约 8% 为审查目标；品牌图标独立按连接状态管理。

**局部光源规则。** 只在顶部身份区外围使用一个低透明度紫罗兰光源，最大可见高度 160px；优先使用静态渐变背景。不得让光影铺到正文、表格或图表读数后面。光源可以移除，信息层级仍应成立。

**对比度规则。** 规范色值按 OKLCH 转 sRGB 后验证：正文对主表面 15.63:1，次要文字 7.79:1，辅助文字 5.54:1，辅助文字对浮层 5.15:1。珊瑚按钮必须使用 ink 深色文字，对比度 7.05:1；text 浅色文字放在珊瑚上只有约 2.24:1，禁止使用。焦点对主表面 9.83:1。详见 [校验记录](validation.json)。这些是令牌配对的结果，不等于已验证生成图或实际页面全部通过。

1.1 新增模块底色的配对检查：辅助文字对 module 为 5.21:1、对 module-primary 为 4.89:1；焦点对 module-primary 为 8.67:1。模块明度拉开后仍保留可读文字与明确焦点。

默认、悬停、选中、禁用、加载和错误必须可区分。悬停采用 raised 底色；选中采用低透明度底色和文字，不使用 2px 以上的侧边色条。禁用状态保留文字可读性，同时移除操作反馈。不能仅依靠色相区分连接和暂停。

## Typography

### 文字角色

| 角色 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| page-title | 24 / 32px | 500 | Agent 名称，一页一处 |
| section-primary | 20 / 28px | 500 | 获客效果等单一主模块 |
| section-secondary | 16 / 24px | 500 | 业务偏好、运营偏好 |
| body | 14 / 22px | 400 | 描述、记录、对话与表单 |
| label | 12 / 18px | 400 | 日期、来源、字段标签、状态补充 |
| metric | 28 / 34px | 450 | 同组指标等宽数字，稳定对齐 |

工作记录与高级摘要的标题使用 body 的字号、500 字重和 secondary 颜色，避免同主模块争夺层级。高级摘要数值使用 14–16px，不能和获客数据同样大。

拉丁与数字优先 Inter，中文使用 PingFang SC，其他平台按字体栈回退。变量字体提供 450；不支持时数值退回 400，不模拟粗体。常规中文不使用 600、700 或细描边；中文正文不设负字距，标题负字距最多约 -0.01em。

**分层规则。** 字号负责角色，字重负责局部强调，灰度负责次序，留白负责分组。优先让同类文本一致，再拉开不同角色。禁止把所有标题、状态和数字都加粗、提亮。

中文单段优先 24–36 字宽；长说明上限约 65–75ch。业务介绍放在标签下方自然换行，不挤入窄表格列。运营偏好的来源集中到一行摘要，详细来源在编辑或悬停中查看。金额使用真实币种、位数与计价说明。

## Elevation

采用稳定画布和低色度模块表面，不以玻璃卡片堆砌深度。独立语义面板使用 module 底色、1px line 完整边界与 12px 圆角；核心效果面板使用 module-primary。边界、表面明度和露出的画布间隙共同表达模块归属。

**模块与条目分工规则。** 模块承担分区，模块里的指标、定义列表和记录行保持轻量。可以给“获客效果”一个完整容器，但不能在其中再给五个指标各套卡片；可以给“工作记录”一个容器，但不能把每条记录再包装成独立卡片。不同语义模块不使用相同尺寸的装饰卡片网格。

- 模块和条目默认无阴影；模块有边界，条目不重复加外框。不同模块之间不得只用一条细线代替画布间隙。
- 仅账号管理弹出面板、菜单和接管浏览器这类覆盖内容需要的层使用柔和遮蔽阴影。正文基底保持稳定。
- 控件圆角 8px、必要独立容器 12px、头像 10px；无意义状态胶囊不列入组件。
- 氛围光是品牌层，浮层是交互层，两者不能混成半透明正文容器。
- 数据更新不做入场编舞；不动画宽高、位置和间距，不使用弹跳。状态过渡 150–220ms，菜单最长 240ms，使用 ease-out-quart 对应的缓动。减少动态效果开启时，移除光源动效和位移，只保留即时状态变化。

## Components

### 操作与输入

主按钮高 36px，单一区域最多一个强强调动作，查看型页面允许没有填充主按钮。珊瑚背景配 ink 深色文字；次要操作采用中性底色或无底文字。编辑、管理、更多与查看全部默认不染珊瑚色。图标按钮桌面点击区至少 32px，触屏至少 44px。

输入框高 40px，标签始终可见；长文本按 14 / 22px 排版。焦点 2px focus 外圈；错误在字段旁显示文字和图标。保存中保留草稿和原位反馈，失败不清空输入。可撤销编辑提供取消入口；并发更新时保留草稿并提示重新核对，不能静默覆盖。

### 身份与社媒栏

头像 40px，默认原创像素角色；名字默认沿用项目命名逻辑，明确编辑后保留用户名称。点击头像或名称旁的编辑按钮，打开同一个“编辑 Agent 资料”弹窗，可修改名称、选择像素头像或上传图片。保存前主页面不切换为表单。静态头像不展示关闭按钮。

11 个社媒图标同时可见，图标 22px。1440px 三栏下名称 12px；1280–1439px 调整为 11px。主区继续变窄后平台自动换行，浮层和状态说明采用 12px。连接后保留品牌色；未连接统一单色灰，只保留一个“连接”入口。已连接且暂停时，图标仍保留品牌色，配暂停符号或文字；连接状态与运营状态是两个不同维度。

常态不铺开开关。点击已连接平台，打开独立账号管理弹窗，展示账号、当前状态及单个平台的启动或暂停操作。未连接平台仍通过唯一入口进入账号连接浏览器。全局暂停为次要紧急入口，不承担日常工作流。图标和状态需要可访问名称及键盘操作。

### 获客效果与网站像素

效果面板占主区完整宽度，以略亮的模块表面和 32px 内边距获得第一阅读权重。标题、时间窗口和像素入口位于面板顶部；指标、趋势与数据覆盖说明在同一面板里依次展开，不能与社媒栏或偏好区混在一个连续平面上。

同组指标统一使用 metric 角色，不做五张独立卡片，不添加虚构增长箭头或 ROI。展示实际可计量的有效访问、访问会话、推广链接点击、已确认发布与服务端转化；无覆盖显示空值并提供就近接入入口，数值 0 只表示已测得为零。

所有数字说明统计窗口和数据口径。当前发布统计若仅提供累计数，标签须明确为“累计发布”，不能暗示跟随近 30 天的访问窗口。有效访问需明确来源于推广归因且满足前台活跃规则；网站访问和转化的覆盖、过期状态分别显示。

趋势线 2px、面积透明度约 6%、两到三条轻水平辅助线；日期和单位为 12px。不铺竖向网格，不让光影遮挡数据。绘制真实时序，空数据不补造曲线。

“网站像素”入口始终出现在效果模块。未接入时显示“接入网站像素”；已接入时显示“网站像素”，进入后仍能查看或复制安装代码。安装在独立对话弹窗中配置，包含网站地址、代码复制、接入状态和最近收到数据的时间；高级回传和推广链接按需展开。弹窗宽 720px，头部、内容和固定底部操作区分开；内容内边距 32px，配置分组间距 28–32px，标签到控件 10px，帮助文字到控件 8–10px。不能把生成代码等同于接入成功。

### 偏好、工作记录和用量

业务和运营偏好直接展示摘要，点击编辑打开独立弹窗，不要求用户先去聊天；长介绍和全部偏好也在弹窗中查看，主页面不原位切换表单或撑高模块。两类偏好各有独立模块底色、边界和 28px 内边距；并列时用 24px 画布间隙分开，不再用一条竖线硬切。目标客户、产品网址与业务介绍采用轻量定义列表。Agent 学到的内容可见且有来源；与用户明确设定冲突时，不能静默覆盖。

工作记录采用独立的全宽低权重面板，和偏好区之间留出 40px 以上的画布。默认三条，完整历史通过“查看全部”在独立弹窗中展示，支持独立的社媒筛选与分页加载。每行平台图标 16px、正文 14px、时间 12px，行高至少 44px；系统行为使用 Agent 图标。区分执行中、完成、失败和待处理，不能统一打成功勾。新记录插入后不抢走用户正在阅读的位置。

高级摘要在工作记录下方独立成区，保留至少 32px 画布间隙；直接显示近 30 天 Tokens、当前额度、浏览器运行时长及预估模型费用。宽主区采用开放的四列定义列表，主区小于 900px 时改为两列；不拆成四张小卡片。缺计价显示“暂无法估算”，部分已计价不得包装为完整总费用。费用币种、计价版本和未计价范围在详情可见。用量数值为 14–16px，额度条只占一行，不与获客结果竞争。

### 辅助对话

桌面固定在右侧，占扣除导航后可用宽度的 38.1966%，主区占 61.8034%，不再使用固定宽度或拖动宽度；对话内边距 24px；标题 14px，消息为 14 / 22px。用户消息用轻表面区分，Agent 消息可直接落在底面。输入框固定在对话底部，独立滚动；对话更新不滚动整个工作台。

对话用于补充信息和调整方向，运营状态、结果、偏好和必要确认都应在主区有对应入口。避免在主区复制整段聊天，也不要求用户每日发消息才能继续运营。

### 账号连接浏览器

从具体平台启动，先在该平台位置展示打开进度，然后进入足够大的专属浏览器接管区域。工具栏仅保留返回、前进、刷新、平台身份及完成验证；点击画面直接输入，支持粘贴、滚轮与输入法，不用额外“回车”“Tab”“删除”按钮教授操作。

界面反馈、账号验证与实时画面分开呈现；显示连接中、失败可重试、验证中和完成。打开登录页不等于账号连接成功。关闭时明确接管结果与当前运营状态，焦点回到原平台。键盘焦点不能被永久困住，Escape 和可见退出按钮可结束接管界面。

浏览器输入不能触发整个工作台重载。性能目标和实际测量应单独验收；本次图片原型不声称已改善运行链路的延迟。

## Do's and Don'ts

### Do

- **Do** 优先让用户在几秒内找到运营状态、有效访问及当前需要处理的事项。
- **Do** 用正文 14 / 22px、12px 可读元信息、32–40px 面板间画布和 48–56px 主组间距建立节奏。
- **Do** 在弱化文字后仍能一眼辨认独立模块，并明确区分主要效果区、配置区和辅助记录区。
- **Do** 保持 400、450、500 的字重分工，让工作记录和用量摘要低于获客模块。
- **Do** 用连接色、运行点和文字分别表示连接与启停，灰色图标只表示未连接。
- **Do** 保留自然滚动，通过弹窗编辑和查看完整内容，保持主页面的结构与阅读位置。
- **Do** 以本文规范值为后续实现依据，生成图用于评估方向与结构。

### Don't

- **Don't** 把参考站的品牌大标题字号、发光主视觉、渐变文字直接搬进产品工作台。
- **Don't** 生成技术控制台、模型参数面板、日志主屏、大量说明文案、多层卡片，或需要每天手动启动的工作流。
- **Don't** 把所有模块塞进一个屏高，或用更小字号隐藏拥挤问题。
- **Don't** 给每行记录和每组指标套卡片、画重分隔线、添加彩色侧边条。
- **Don't** 给未连接平台同时放“未连接”、连接按钮和禁用开关。
- **Don't** 把所有链接染成珊瑚色，或把操作色和错误色混用。
- **Don't** 用无来源的流量、增长率、转化或费用装饰页面。
- **Don't** 把模型调用、接管工具、任务编排等实现细节塞进面向普通用户的主流程。

## Implementation

- 令牌唯一入口：[design-tokens.css](../apps/web/app/design-tokens.css)。色彩使用 OKLCH，字体为本地 Inter Variable 与中文系统字体栈，不依赖外部字体请求。
- 布局与响应式：[styles.css](../apps/web/app/styles.css)。桌面 1440px 三栏，主区独立滚动；低于 1280px 对话按需展开；小于 768px 使用全屏辅助对话。
- 身份、社媒、获客、偏好、工作记录、用量分别在独立组件中维护；数据和操作均接入现有服务，不能加入原型中的示例结果。
- 像素头像为原创透明位图。平台标识来自 Simple Icons，LinkedIn 使用 Lucide 的品牌图标；通用操作延续 Lucide，图标不混用实心装饰插画。
- “访问会话”以有推广归因的真实会话为口径，不声称为去重人数；趋势与指标使用相同近 30 天滚动窗口，按北京时间分日。累计发布独立标注累计口径。
- 用量每 30 秒更新；费用缺计价时保留未知。部分计价必须标注未计价调用数量；当前日额度保留即时编辑和恢复默认值。
- 账号浏览器采用 JPEG 画面、单请求轮询、输入队列与文字合并；切换画面和输入不触发整个工作台重载。PNG 仍用于证据留存。
- 视觉与交互核对记录见项目根目录 [design-qa.md](../design-qa.md)。未来增加界面，先复用令牌和语义角色，再扩展组件。


## 1.2 交互与细节补充

- **黄金分割**：桌面运营主区与辅助对话使用精确比例 61.803398875% : 38.196601125%，全局导航不参与计算。1440px 时约 776 / 480px；1920px 时约 1073 / 663px。主区小于 840px 时，社媒图标分两行，避免为了保留单行而缩小文字。
- **滚动**：工作台、消息、弹窗、代码等区域均隐藏滚动条外观，保留原有滚动机制。工作台、对话记录与弹窗内容可用键盘聚焦和滚动；不得以 `overflow:hidden` 代替隐藏滚动条。主区不预留滚动条槽位。
- **工作记录筛选**：使用带可访问名称的原生平台选择器，包含全部社媒和 Agent 系统记录。平台过滤先于服务器的 50 条上限，切换时保留加载、无记录和失败重试状态。
- **高级设置**：主页面只展示用量摘要；“更多”打开独立弹窗，内容按额度、费用与数据、浏览器环境、测试和归档分组。组间以 28px 留白和完整细分隔线组织；输入宽度 280px，字段说明与操作区有独立间距。窄屏动作换行，按钮不紧贴帮助文字。
- **创建向导**：先弹出分步对话，依次收集产品名称、网址、介绍、受众、运营目标、内容期望、策略倾向；随后选择首个渠道并进入登录浏览器。登录验证通过后完成创建、进入 Agent 主页面。其他渠道可在主页面继续连接。
- **草稿与状态**：用于承载独立浏览器的创建草稿不出现在正式 Agent 列表，不启动运营；可恢复未完成的流程。取消仅清理尚未完成的草稿，已完成创建的 Agent 不受迟到的取消请求影响。
- **对话弹窗**：采用原生模态语义、背景遮蔽、焦点约束、Escape 退出与关闭后焦点恢复。头像名称、偏好编辑、完整记录、渠道管理、高级设置、像素设置与创建向导共用同一弹窗基础组件，禁止把多个配置项连续平铺进主工作台。

- **对话输入焦点**：消息输入框内部不绘制紫色选中框；使用外层 composer 的中性灰细边界变化表达焦点。键盘操作仍保留其他控件的明确焦点指示。


## 1.3 弹窗交互规范

主工作台提供稳定摘要。所有“编辑”“更多”“查看全部”和完整资料入口均打开独立模态弹窗，不在主页面切换为表单、插入详情或改变模块顺序。筛选和实时数据更新仍作用于所属摘要。

| 入口 | 弹窗内容 | 桌面宽度 |
| --- | --- | --- |
| 头像、名称编辑 | 资料预览、名称、默认像素头像、上传图片 | compact，560px |
| 已连接社媒 | 账号信息、运营状态、单渠道启停、重新登录 | compact，560px |
| 业务或运营偏好编辑 | 带标签的编辑表单及保存、取消 | default，720px |
| 完整业务介绍、全部运营偏好 | 完整内容、来源、编辑入口 | default，720px |
| 高级设置、网站像素 | 分组配置、说明及就近反馈 | default，720px |
| 全部工作记录 | 独立平台筛选、刷新、每次 50 条、更早记录 | wide，960px |
| 浏览记录、内容与运营准备 | 步骤和证据、素材与复盘 | wide，960px |

- 共用 `DialogPanel`：原生模态语义、背景遮蔽、标题与说明、可滚动内容、固定底部操作。桌面标题区 28/32/24px，内容区 28/32/32px，底部 20/32px；窄屏保留 12px 外边距，内容边距 20px。
- 表单组间距 28px，标签到控件 10px，帮助文字 10px。头像预览和选择分组独立，选择区桌面八列、手机四列。使用相同字重、圆角与中性色。
- 打开时焦点进入弹窗，背景不可操作；Tab及Shift+Tab在当前弹窗首尾循环；Escape、关闭按钮或遮罩可退出。弹窗隔离Escape和Tab的冒泡，避免背景手机对话同时处理按键。关闭后焦点回到原入口且不触发额外滚动，主区阅读位置保持。保存或上传中避免重复提交。
- 草稿仅存在于弹窗中。取消不修改 Agent 名称、头像或偏好；保存成功后刷新摘要再关闭。接口错误留在当前弹窗，失败保留输入；并发修订冲突不静默覆盖。图片上传暂存素材，身份仅在保存后更新。
- 完整工作记录的筛选不改变主页面筛选。服务器先按平台过滤，再按时间与 ID 排序分页；支持空状态、加载、失败重试。默认摘要仍为三条。
- 弹窗内部可用低权重折叠项组织高级说明；不得将这些展开内容插回主工作台。切换到账号浏览器前关闭当前设置弹窗，避免原生顶层覆盖浏览器操作。
- 统一入口图标：弹窗查看使用 ArrowUpRight，编辑使用 Pencil；不使用“收起”或旋转箭头暗示主页面展开。
