# Lead 自主运营架构

当前实现规格为 [自主运营运行时 V2](requirements/20261112-autonomous-growth-runtime.md)。本文件说明模块分工；精确状态、命令、失败场景和验收以该需求记录为准。

## 一个判断入口，独立持久工作

每项目一个经营 Agent 根据产品、来源、当前能力和实际反馈决定下一步。运行器只推进已经接受的固定任务，不承担第二套渠道策略。工具只完成有边界的读取、制作、连接、提交、核对或恢复。

继续使用 Web/API、Worker、浏览器、PostgreSQL 与 Temporal，不增加新的微服务或消息总线。一个渠道等待只占用相关资源；模型决策、普通工作和确定性回执有独立执行容量。

| 模块 | 具体职责 | 写入边界 |
| --- | --- | --- |
| `growth/agent.py` | 组装有来源的上下文、经营判断、一次定向结构修正 | 只能提出声明的命令，不能直接写权限或回执 |
| `growth/store.py` | 任务引用、实验与问题投入、命令组原子接收、用户项目控制 | 数据库事务同时保存任务与 outbox；独立组分别接收 |
| `growth/runtime.py` | 固定领取、完成、等待、故障累计、原任务恢复、到期补偿 | generation/尝试令牌隔离迟到控制；不重置已投入费用 |
| `growth/tools.py` | 公开来源、内容宏任务、固定渠道操作、观察与恢复工具 | 输入严格校验；实际执行前重核当前引用 |
| `account_connection.py` | 登录后自动观察、原子完成、独立目标发现 | 身份证明来自当前专属会话；歧义不猜测 |
| `account_intents.py` | 连接派生、用户暂停/恢复/撤销 | 受控来源函数；旧运行器不能伪造新意图 |
| `execution_routes.py` | 按账号/Profile/原动作解析登记的执行器 | 模型不能提供任意 RPC 地址；未知动作使用原执行位置 |
| `growth/outcomes.py` | 冻结口径、主体去重、首次来源、未知与真实成果 | 浏览器事件不冒充服务端成果；旧口径不证明新口径 |
| `growth/views.py` | 目标、工作、结果、局部等待与工作证据查询 | 读取不派活；用户按钮与对话共用控制事实 |
| `growth/migration.py` | 操作员预览、指纹校验和运行归属转移 | 不向模型开放；保留旧未知动作身份、原范围与费用 |

## 唯一事实

新增三类记录：`growth_experiments`、`account_operating_intents`、`profile_execution_routes`。继续使用 tasks、actions/attempts、内容/素材、业务事件、费用与 outbox；不另建平行账户工作流或营销计划表。

任务固定七类：decision、research、content、account、channel、observe、recover。Macro 内的上传、制作、提交与核对以检查点推进同一任务。仅在共享或独立素材确有必要时拆任务。

复合外键、FORCE RLS、工作室/项目作用域和角色授权共同约束引用。账号意图及完成连接由受控函数写入；运行角色不能伪造连接源事件。生成的内容和外部动作保持固定快照，迟到真实回执可以补账。

## 并行与故障

数据库短事务负责领取和校验。模型、网页和媒体处理不持有 Agent 排他锁。提交对项目控制、具体账号与意图取得兼容读锁；暂停与实际点击有确定顺序，独立 Profile 可以重叠执行。

Wait 必须包含原因、具体生产者、作用域、下次检查、恢复动作及责任。等待不占 Activity、模型额度或其他 Profile。到期扫描持久轮转，避免第一批健康记录遮住后面的到期/费用耗尽工作。

业务失败按实际资源与条件累计，初值三次；结构修正初值一次。相同故障换任务名、重启或重复事件不会重新得到额度。低频恢复探测只有证明原失败条件已恢复，才能继续原任务一次。进程心跳不会延长有意义进展期限。

## 工具与渠道

公开研究默认直读受控公网来源，必要时使用独立公开研究 Profile。搜索索引只提供候选链接，原文读取后才形成来源证据。来源正文均为不可信数据，不能指挥权限、工具或 SQL。

内容不依赖计划表或账号。媒体制作嵌入 content 宏任务，使用原任务检查点和资产校验；可选媒体失败不阻断合适的文字路径。相同内容和目标不能靠重命名任务产生第二次相同提交。

渠道方法只提供可选知识；实际可用操作以安装的工具和适配器为准。首次正常业务发布可形成对应格式能力证明，但仍需满足真实角色、许可、内容、素材和执行环境条件。诊断与正式业务分别记录。

账号连接不要求项目暂停。身份观察使用独立页面，不长期锁住人工输入。稳定标识相同不提升绑定版本；仅有账号名且发生无法证明的变化时保留歧义。登录不覆盖主动暂停。解除绑定撤销该关系的意图，旧未知回执保留。

## 成果与费用

实验前冻结业务事件、定义版本、user/pair/order/organization 主体、新客规则、排除项、归因窗口与迟到容许。核心成果来自可信服务端事件及首次业务证据；无历史或证明时为未知。

项目内跨渠道主体去重，主来源来自首个合格获客到站，其他接触保留为辅助。来源必须能串回内容与已确认的真实发布；邀请单列，测试/团队/合作方验收/诊断排除。迟到事实产生新的可复现报告版本，不重发已结束的动作。

模型调用先预留、后按实际用量结算；未知计费继续占用。项目、实验及同问题的 variation 累计投入。产品名称不能触发无限额度或把业务目标改成点击。

## 迁移与实际执行器

0031 在 schema 切换时先设置迁移中的运行归属，数据库拒绝旧派活和新的旧式原生发送。操作员按预览指纹转移项目；技术 generation 不修改用户控制。既有暂停、范围、限制和费用保留。

旧 actions 的未知提交转为原动作核对，保留 operation_key/intent。旧原生入群/回复只由受限回执消费者读取持久目标和原文；不会阻止其他资源切换。旧 TaskWorkflow、Supervisor、渠道时钟和私有 resident 不再选择新工作。

独立执行器必须核对真实入口、只读主线镜像、私有适配器清单、原 Profile、实际 PID/InvocationID 与启动回执。Telegram 新入口只提供明确浏览器操作及旧回执读取，经营选择由公共 Agent 完成。应用 SHA 不能代替实际执行器交付证明。

本轮尚未完成生产切换；交付状态与证据持续记录在需求记录和待办中。
