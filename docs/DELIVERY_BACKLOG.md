## M5 渠道扩展

每个平台的每个动作使用同一张验收表。责任人记录账号类型、目标类型、地区、浏览器与适配器版本、许可材料、已通过用例、限制和熔断方式。十一渠道名称不等于十一渠道已经全部开放。

验收表字段：平台、动作、目标、用户授权、平台许可、登录验证、账号确认、媒体支持、准备边界、最终提交边界、结果核对、半提交恢复、接管、数据可见性、最后测试日期、维护负责人。

X 和 LinkedIn 在适用许可条件解决前保持自主写入关闭。其他平台也必须实际审查。任一渠道故障仅关闭受影响能力，不能停止整个工作室。

## 发布前必过场景

- 聊天输入网址，Agent 逐步引导，信息足够后不再重复提问。
- 用户明确说「多分享使用技巧」，偏好生效并有回执；仅讨论假设时不偷偷改配置。
- 用户询问「今天做了什么」「流量从哪来」，回答引用当前 Agent 的真实状态和数据范围。
- 对话暂停和页面暂停走同一个控制逻辑；已提交动作保留核对状态。
- 同时运行三个 Agent，操作区间重叠，暂停和崩溃互不串扰。
- 数据库查询、向量检索、缓存、文件、消息和浏览器连接的跨 Agent 请求均被拒绝。
- 同一外部账号不能被两名活动 Agent 同时绑定控制；账号目标与授权目标一致。
- 提交前、点击后、收到成功页前后分别断开执行器，验证不会盲目再发。
- 出口断开后，HTTP、HTTPS、WebSocket、媒体、DNS、IPv6 和适用 WebRTC 测试不从宿主其他出口泄漏。
- 控制节点失联后，不以数据库租约到期为唯一依据启动同 Profile 第二个写实例。
- 用户接管断线后，Agent 不继续操作半完成的页面。
- 重复用户消息、事件、工作流 Activity 和转化事件均不重复应用业务结果。
- 未接网站数据时不显示虚构有效访问；采集断开不显示为真实零值。
- 浏览器更新和备份恢复完成后，身份、账号、授权及动作账本得到复核。
- 正常运营保持安静，必要登录或授权事项合并通知，不要求用户每天启动。
